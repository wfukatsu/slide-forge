# ピクトグラムとメタファー図

`scripts/illustrations.py` は図形だけで 2 種類のものを描く。

1. **ピクトグラム** — 1 つの意味を 1 つの絵で表す（`person`、`server`、
   `database`）。`icon()` / `icon_row()` / `icon_flow()` / `icon_grid()` で置く。
2. **メタファー図** — 関係そのものの形（`pyramid`、`funnel`、`iceberg`、
   `balance`）。いずれも `Canvas` のメソッド。

画像アップロードも API キーもネットワークも要らない。色はテンプレートの
パレットから取るため、再生成しても同じ絵になり、テーマ変更にも追従する。

**名前の一覧はこの文書には無い。** CLI が 3KB で出力し、しかもコードから
読むので実装とずれない。

```bash
.venv/bin/python scripts/illustrations.py --list           # ピクトグラム 32 + 図 17
.venv/bin/python scripts/illustrations.py --search flow    # 名前・説明の部分一致
```

この文書が扱うのは、その周りの判断である — どの図を選ぶか、どの大きさで
描くか、何をすると読めなくなるか。描画 API は [diagrams.md](diagrams.md)、
写真や生成画像は [images.md](images.md)、「証拠チェーン」のような業務語彙を
表す Scalar 独自のピクトグラムは [icons.md](icons.md) を見ること。

## 1. 図形が画像に勝つとき

| | 図形で描く | 画像（`d.image` / `d.ai_image`） |
|---|---|---|
| 再現性 | 毎回同じ | AI 画像は毎回変わる |
| テーマ変更 | 追従する | 作り直しが要る |
| 拡大縮小 | ベクタで劣化しない | 解像度に縛られる |
| コスト | アップロードも鍵も不要 | Drive アップロード / Gemini キー |
| 表せるもの | カテゴリ（サーバ、利用者） | 特定の場面、実際の画面 |

カテゴリでは足りない情報を絵が担うとき — 製品画面、写真、表紙の雰囲気 —
だけ画像を使う。「ここにデータベースがある」を言うだけなら、図形のほうが
安く安定している。

## 2. 図の選び方

書いている**話題**ではなく、示している**関係**に合わせる。セキュリティの
スライドだから `shield` なのではない。セキュリティが他のすべての下にあると
示すなら `layers` である。

| 示したい関係 | 図 |
|---|---|
| 主体から主体へ渡っていく工程 | `icon_flow` |
| 順序のない集合 | `icon_row` / `icon_grid` |
| 上ほど少ない階層 | `pyramid` |
| 段階ごとに絞り込まれる | `funnel` |
| 2〜3 者の重なり | `venn` |
| 見えている一部と、その下の本体 | `iceberg` |
| 2 案のトレードオフ | `balance` |
| 前の段に乗って登っていく | `steps` |
| 下の層に支えられた積み重ね | `layers` |
| 1 つの中心と多数の周辺 | `hub` |
| 2 軸 4 象限 | `matrix` |
| 選択肢の横並び | `comparison` |
| 同じ対象の前後 | `before_after` |
| 経路や期間上のマイルストーン | `journey` / `timeline` |

どの関係にも当てはまらないなら、それは表かグラフである。
[charts.md](charts.md) と [patterns.md](patterns.md) を見ること。

## 3. 大きさ

`size` はピクトグラムを描く正方形の一辺（インチ）。

| 用途 | 大きさ | 下限 | 備考 |
|---|---|---|---|
| 本文の脇にインラインで | 0.30〜0.40 | 0.25 | 行の高さに合わせる |
| カードの中 | 0.40〜0.60 | 0.35 | カード幅の 20〜30% |
| グリッドの中 | 0.50〜0.70 | 0.40 | セル幅の 25〜35% |
| そのページの主役 | 0.80〜1.20 | 0.60 | |
| 表紙のヒーロー | 1.50〜2.00 | 1.00 | |

ページは 10.0 × 5.625in（Slides は 16:9 を PowerPoint の 0.75 倍で正規化する）、
図を描ける範囲は y 0.84〜4.30。`deckkit` の `X0 / W / DY0 / DY1` を参照。

図形の**中**に文字を置くときのサイズ:

| 図形 | 1 文字 | 2〜3 文字 | 4 文字以上 |
|---|---|---|---|
| 0.3in | 12pt | 8pt | 入らない |
| 0.4in | 16pt | 10pt | 8pt |
| 0.5in | 18pt | 12pt | 9pt |
| 0.6in | 22pt | 14pt | 10pt |
| 0.8in | 28pt | 18pt | 12pt |
| 1.0in | 36pt | 22pt | 14pt |

**8pt が下限。** 7pt を切ると可読性が急に落ちる。`audit_text_fit()` は助けに
ならない — 枠に収まるかは見るが、読めるかは見ない。

## 4. 色

色は意味で選ぶ。テンプレートの `colors` から組み立てたパレット（`d.P.*`）を
使い、16 進数を直書きしないこと。テンプレートを差し替えても資料がついてくる
のがパレットの存在理由である。

| その要素が何か | パレット |
|---|---|
| 自社製品 | `d.P.primary` |
| 外部システム | `d.P.muted` |
| 利用者・クライアント側 | `d.P.warning`（塗りとして。下記参照） |
| 成功・正常系 | `d.P.success` |
| 失敗・異常系 | `d.P.danger` |
| 新規・強調 | `d.P.info` |
| 背景ゾーンと罫 | `d.P.surface` / `d.P.border` |

`tone_colors(d, tone)` は `primary` / `info` / `good` / `warn` / `bad` /
`muted` / `accent` に対応する（塗り・枠・文字色）の組を返し、
`tone_solid(d, tone)` は濃い単色を返す。3 色を手で選ぶより、こちらを使う。

scalar-2026 のパレットを白地で実測した値:

| 色 | Hex | 白地のコントラスト | 文字色として |
|---|---|---|---|
| `text` | `#0F172A` | 17.9:1 | 可 |
| `primaryDark` | `#194B7A` | 9.0:1 | 可 |
| `primary` | `#2673BB` | 4.9:1 | 可 |
| `muted` | `#6B7280` | 4.8:1 | 可 |
| `danger` | `#EE2155` | 4.2:1 | 大きな文字のみ |
| `info` | `#0985FD` | 3.6:1 | 大きな文字のみ |
| `success` | `#63C045` | 2.3:1 | **塗り専用** |
| `warning` | `#FFEF24` | 1.2:1 | **塗り専用** |

> `success` と `warning` は塗りであって文字色ではない。白地に緑、白地に黄は
> どちらも AA を満たさない。その上に白か `text` を載せること。

塗りと枠:

| スタイル | 用途 | 指定 |
|---|---|---|
| ベタ塗り | 主役の要素 | `fill=c, stroke=None` |
| 枠線のみ | 補助的な要素 | `fill=None, stroke=c` |
| 薄い塗り＋濃い枠 | 強調したい補助要素 | `fill=lighten(c, 0.85), stroke=c` |
| 濃い帯の上 | 暗い背景に載せるとき | `fill=d.P.page, stroke=c` |

## 5. 行・グリッド・フロー

```python
d.icon_row(0.5, 1.3, 9.0, [("person", "利用者"), ("browser", "アプリ"),
                           ("database", "台帳")], size=0.8)
d.icon_grid(0.5, 1.3, 9.0, ["server", "cloud", "lock", "chart"], cols=4)
d.icon_flow(0.5, 2.6, 9.0, [("person", "申込"), ("bot", "審査"),
                            ("database", "記録")], size=0.92)
```

`icon_flow` は矢印を通す隙間を必要とし、隙間が取れないときは重ねて描くのでは
なく例外を投げる。エラーには収まる最大の size が出るので、その値にするか、
`w` を広げるか、矢印の要らない `icon_row` に落とすこと。

先に衝突するのはピクトグラムではなくキャプションである。**描いたら
`audit_overlaps()` と `audit_text_fit()` を必ず実行する** — 0.5in のアイコンに
長いラベルを付けた、が典型で、API を呼ぶ前の座標段階で捕まえられる。

## 6. 図形を使わない Unicode 記号

インラインの印なら、本文中の 1 文字で足りる。図を起こす必要はない。

| 文字 | コード | 用途 | Noto Sans JP / Arial |
|---|---|---|---|
| ✓ | U+2713 | 対応・完了 | 確実に出る |
| ✗ | U+2717 | 非対応・失敗 | 確実に出る |
| ● ○ | U+25CF / U+25CB | 塗り／空の印 | 確実に出る |
| ▶ | U+25B6 | 次へ | 確実に出る |
| ◆ | U+25C6 | 強調の印 | 確実に出る |
| ★ ☆ | U+2605 / U+2606 | 評価済／未評価 | 確実に出る |
| → | U+2192 | 流れ・方向 | 確実に出る |
| ⬆ ⬇ | U+2B06 / U+2B07 | 増・減 | 確実に出る |
| ∞ | U+221E | 無制限 | 確実に出る |
| ⚡ ⚙ | U+26A1 / U+2699 | 高速／設定 | 環境差あり。ピクトグラムを使う |

カラー絵文字（🚀 💡 📊）は環境で見え方が変わるので、意味を担わせない。

## 7. 図のリクエスト消費

`batchUpdate` は 500 リクエストで区切られる。ピクトグラムの多いページは
見た目より早く積み上がる。

| | 1 個あたり |
|---|---|
| 単純な図形 | 2〜3 |
| 文字を持つ図形 | 5〜7 |
| 下にキャプションを付ける | +4 |

キャプション付き 6 セルの `icon_grid` は、それだけで 40〜60 リクエストになる。
効く手は 2 つ。グリッド脇の本文が既に説明しているならアイコン個別の
キャプションを省くこと、✓/✗ の印は図形ではなく Unicode 文字にすること。

## 8. 注意

- **1 つの複合ピクトグラムは図形 3 つまで。** それ以上は記号ではなく雑音に
  なる。
- **後に描いた図形が前面に来る。** 背景を先に描くこと。監査に「後から描いた
  図形に文字が隠れている」検査があるのは、これを取り違えやすいからである。
- **子図形の寸法は `size` に対する比で決める。** 絶対インチで書くと、縮尺を
  変えた瞬間に崩れる。
- **ラベルは図形の外に置く。** 1〜2 文字でない限り、中に入れない。

## 付録. shapeType 早見表

概念 → Slides の `shapeType`。既製のピクトグラムではなく
`d.shape(..., kind=...)` で自分で図形を描くときに使う。

| 表したいもの | shapeType | 代替 |
|---|---|---|
| データベース | `CAN` | `FLOW_CHART_MAGNETIC_DISK` |
| ファイル・文書 | `FLOW_CHART_DOCUMENT` | `FOLDED_CORNER` |
| クラウド | `CLOUD` | `CLOUD_CALLOUT` |
| サーバ・機器 | `ROUND_RECTANGLE` | `RECTANGLE` |
| セキュリティ | `PENTAGON` | `FLOW_CHART_PREPARATION` |
| 処理ステップ | `FLOW_CHART_PROCESS` | `RECTANGLE` |
| 判断・分岐 | `FLOW_CHART_DECISION` | `DIAMOND` |
| API・サービス | `ROUND_RECTANGLE` + 文字 | `HEXAGON` + 文字 |
| コンテナ | `CUBE` | `ROUND_RECTANGLE` |
| ネットワーク | `HEXAGON` | `OCTAGON` |
| キュー・ストリーム | `CHEVRON` | `RIGHT_ARROW` |
| ゴール・的 | `DONUT` | `STAR_5` |
| 重要・優先 | `STAR_5` | `STARBURST` |
| 禁止 | `NO_SMOKING` | `MATH_MULTIPLY` |
| 高速・性能 | `LIGHTNING_BOLT` | Unicode ⚡ |
| 方向・流れ | `RIGHT_ARROW` 系 | `CHEVRON` |
