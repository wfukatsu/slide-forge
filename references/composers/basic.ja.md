# 骨格ページの組み立て

デッキの主張ではなく、デッキの骨格を担うページ — 表紙・目次・章扉・サマリ・
裏表紙・付録。いずれもテンプレートのレイアウトが既に面倒を見ている領域なので、
方針はすべて共通で、**プレースホルダのレイアウトを使い、自分で描かない**。
手で描いた表紙は、ブランドが変わった瞬間にマスターへの追従をやめる。

```python
plain(layout="COVER", title="…", subtitle="…", body="2026-08-22\n株式会社Scalar")
```

デッキ spec なら:

```json
{"layout": "COVER", "title": "…", "subtitle": "…", "body": "2026-08-22"}
```

どのロール名が使えるかは `templates/<id>.json` にあり、`list_templates.py` が
表示する。標準の 6 つは COVER / SECTION / CONTENT / TITLE_ONLY / BLANK /
CLOSING。

## 表紙

題名、サブタイトル、誰がいつ話すか。背景・ロゴ・帯はマスターが持ち、デッキが
渡すのは 3 つの文字列だけ。

**作り方**: `layout="COVER"` — `title`、`subtitle`、`body`（発表者と日付を
改行で）。

題名は 1 行に収める。判定は `deckkit.fits_one_line()`（`TITLE_EM_MAX`、20pt で
全角 30.5 文字相当）。折り返した表紙題名はサブタイトルを押し出す。

## 目次

章立てを番号付きで並べ、議論の長さを読み手に見せる。8 枚を超えるあたりから
価値が出る。それ未満では、節約する注意より奪う注意のほうが多い。

**作り方**: `layout="CONTENT"` — `body` を 1 章 1 行のリストで。進捗を示す
目次を章扉ごとに繰り返すなら、項目を淡くするのではなく章ごとに
`layout="SECTION"` を置く。

## 章扉

章番号と章題を中央に。役割は情報ではなく「区切り」である。

**作り方**: `layout="SECTION"` — `title`、必要なら章の内容を 1 行で `body` に。

## エグゼクティブサマリ

議論の前に結論を置く。これだけはプレースホルダのページではない — 構造を
持つので図になる。

**作り方**: `exec_summary` 図（状況・複雑化・解決と、支える論点）、または
読み物用途なら `exec-summary-readable` テンプレート。
[slide-patterns.md](../slide-patterns.md) を参照。

## 裏表紙

ロゴと連絡先。マスターが既に持っていることが多い。

**作り方**: `layout="CLOSING"`、中身なし。`deck.add_slide("CLOSING")`。

## 付録の扉

本編の議論がここで終わり、以降は補足であると示す。

**作り方**: `layout="SECTION"`、題名は Appendix。議論を追うために読み手が
見なければならないものは、この後ろに置かない。
