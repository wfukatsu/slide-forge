# レイアウト契約（座標と実測値）

図解デッキが崩れる原因はほぼ座標にある。ここに書いた数値は 16:9（10 × 5.625in）の
テンプレートで**実際に生成して測った**値。推測ではない。

## 座標系

- 単位はインチ。原点はスライド左上。x は右、y は下が正。
- 内部的には EMU（1in = 914,400 EMU）。`_auth.inches()` が変換する。
- Google Slides の既定は 10 × 5.625in。テンプレートの `pageSize` で確認する。

## 安全域

```
y=0.000  ┌──────────────────────────────────────────┐
         │                                          │
y=0.126  │  ■ TITLE プレースホルダ（h=0.351）        │  ← 1 行なら y=0.48 で終わる
y=0.480  │                                          │
         │  ← ここから下がタイトルの「下」            │
y=0.840  │ ┌──────────────────────────────────────┐ │  DY0：図の上端
         │ │                                      │ │
         │ │        図を描いてよい領域              │ │  高さ 3.46in
         │ │                                      │ │
y=4.300  │ └──────────────────────────────────────┘ │  DY1：図の下端
y=4.380  │  要点行（最大2行 / 10.5pt）               │  NY   ← foot() が描く
y=4.860  │  提供・補足行（1行 / 9pt）                │  EY   ← foot() が描く
y=5.197  │  ■ マスターのロゴ・著作権フッター          │  ← ここから下は触らない
y=5.625  └──────────────────────────────────────────┘

x=0.5 ─────────── 描画幅 W=9.0 ─────────── x=9.5
```

`deckkit` の定数: `X0=0.5` `W=9.0` `XE=9.5` `DY0=0.84` `DY1=4.30` `NY=4.38` `EY=4.86`

ラベルは中央寄せの都合で枠から少しはみ出すため、検査は左右に 0.25in の余裕を認める。

## タイトルは 1 行に収める

**タイトルが 2 行になると `DY0` を越えて図と重なる。** これが一番多い崩れ方。

判定は全角換算幅（全角=1.0、半角=0.5）で行う。20pt bold での実測:

| 全角換算幅 | 結果 |
|---|---|
| 31.0 | 1 行に収まった |
| 33.0 | 2 行になった |
| 35.0 / 36.0 | 2 行になった |

→ 上限を **30.5** に設定（`TITLE_EM_MAX`）。`deckkit.em(title)` で測れる。

タイトルサイズが違うテンプレートでは上限も変わる。目安は `幅(pt) ÷ フォントサイズ(pt)`
の 0.95 倍程度（20pt / 9.0in の場合 648 ÷ 20 × 0.95 ≈ 30.8）。

## 本文プレースホルダの行数

Google の `lineSpacing` は**フォント本来の行高に対する百分率**で、絶対値ではない。
Noto Sans JP の行高は約 1.45em なので、実際の 1 行の高さは:

```
行高(in) = フォントサイズ(pt) × 1.45 × lineSpacing(%) ÷ 100 ÷ 72
```

| 設定 | 1 行の高さ | h=4.068in に入る行数 |
|---|---|---|
| 13pt / 160% | 0.419in | 9.7 行 |
| 12pt / 120% | 0.290in | 14.0 行 |
| 12pt / 115% | 0.278in | 14.6 行 |

`deckkit` の既定は **12pt / 120%（最大 14 行）**。13pt / 160% で 12 行入れると
フッターを突き破る（実際にそうなった）。

1 行に入る文字数は `幅(pt) ÷ フォントサイズ(pt)`。9.0in / 12pt なら全角 54 文字。
折り返しを避けたいなら全角 46 文字程度に抑える。

## パーツを積むときの高さ

`zone` の中身は見出しと重ならないよう `y + 0.34` 以降に描く。

| パーツ | 標準の高さ | 備考 |
|---|---|---|
| `zone` の見出し | 0.34 | 中身はこの下から |
| 箱（1 行） | 0.30〜0.36 | 8〜9pt の文字 |
| 箱（2 行） | 0.44〜0.52 | `line_spacing=105〜110` を付ける |
| 箱（見出し＋説明） | 0.62〜0.80 | 見出し 0.24＋説明 |
| `grid` の見出し行 | 0.30〜0.32 | |
| `grid` のデータ行 | 0.245〜0.30 | 行数が多いなら 0.245 まで詰められる |
| `pills` の 1 段 | 0.19〜0.28 | `gap` は 0.04〜0.08 |
| `Canvas.cards` | 0.72〜1.05 | 見出し＋本文 2〜3 行 |
| `db`（円柱） | 0.42〜0.60 | **下に 0.22in（sub 付きは 0.42in）ラベルがはみ出す** |
| 全幅バナー | 0.34〜0.52 | |
| 縦の矢印 | **0.12 以上** | 0.10 以下は描画されず点のように見える |

`db()` のラベルは図形の外に出るので、下端の計算に含めること。忘れると検査で落ちる。

## 崩しがちなパターン

| やったこと | 何が起きたか | 正しくは |
|---|---|---|
| 13pt / 160% で 13 行 | 最終行がフッターに重なった | 12pt / 120%、最大 14 行 |
| タイトルを 33 文字 | 2 行になって図に被った | 30.5 全角文字以内 |
| 右パネルの幅を 1.15in | 文字が枠外に溢れた | 幅を配り直す。狭ければ下段の全幅カードに移す |
| レーンをまたぐ矢印を水平に引いた | 矢印が空中で途切れて見えた | 始点・終点の実座標を結ぶ（対角線でよい） |
| ラベルを矢印の真上に置いた | 罫線と重なって読めない | `align` を START/END にして外側へ寄せる |
| ループの戻り矢印を本文の上に通した | 文字を横切った | 列間の余白を通るエルボー（3 本の線）にする |
| 矢印を 0.10in で描いた | 点のように見えた | 0.12in 以上 |
| 矢印の端点を座標で書いた | 図形から浮いた／内部に埋まった | `connect()` か `link()` で図形を指定する |
| `zone` の外にラベルをはみ出させた | 下のブロック（表の見出し行）と重なった | 補足はマーカーや箱の内側に持たせる |

## 検査器が見るもの・見ないもの

`validate_layout.py` は座標だけで分かる不具合を 8 種類拾う。

| 見る | 内容 |
|---|---|
| はみ出し | 図がフッター領域（`DY1`）や左右の外に出ている |
| タイトル | 2 行になって図の領域を侵食する |
| 描画例外 | 座標計算のミス |
| レイアウト | ロール名・プレースホルダの不整合 |
| コネクタ | 端点がどの図形にも接していない／図形に埋まっている |
| **隠れ** | ある文字より**後に描かれた**不透明図形がその文字を覆っている |
| **衝突** | 塗りの無いラベルどうしが、実際に文字が載る範囲で重なっている |
| **文字溢れ** | 必要な行数が枠の高さを超えている |

隠れの判定は Slides の描画順（後の要素が上）を使う。バナーやゾーンを直前のブロックに
重ねてしまう典型的な事故がこれで落ちる。入れ子（ゾーンの中に中身を置く）は正常なので
報告しない。衝突の判定は枠ではなく**文字が実際に載る範囲**で行う。枠で判定すると、
余白の広いラベルが隣に少しかかっているだけで大量の誤検出になる。

**見ないもの**（サムネイル目視が必要）:

- 矢印が他の図形の**上を横切っていないか**（接続の有無は分かるが、経路の良し悪しは分からない）
- 矢印が「正しい図形」に繋がっているか（A→B のつもりで A→C でもエラーにならない）
- コントラスト、図が伝えたいことを実際に伝えているか

## 固定比率で領域を割らない

箱の高さに対して「見出しに 0.7in」「数値に 52%」のような固定配分をすると、
箱が小さいときに中身が潰れて文字が切れる。実際にこれで 4 つの部品が壊れていた。

| 部品 | 壊れ方 | 直し方 |
|---|---|---|
| `Canvas.cards` | 本文領域を `h - 0.70` で取り、`h=0.82` のとき本文が 0.12in しか残らず切れた | `h - 0.58` に緩和 |
| `stats` / `Canvas.metric` | 数値のフォントが固定で、枠が低いと溢れて説明とぶつかった | **枠高からフォントサイズを算出して自動縮小** |
| `cycle` | 半径が小さいと向かい合う箱どうしが衝突した | 箱幅を半径に合わせて自動調整 |

**部品は与えられた領域に収まるよう自分で縮む**べきで、呼び出し側の指定を信じて
はみ出してはいけない。新しい部品を書くときは、`h` を極端に小さくして
`audit_text_fit()` が通るかを確かめる。

## ページサイズが違う場合

```python
configure_layout(page_w=13.333, page_h=7.5, margin=0.6,
                 diagram_top=1.0, diagram_bottom=5.9,
                 note_y=6.0, edition_y=6.5, title_em_max=40)
```

決め方:

1. `diagram_top` = テンプレートの `elements.title` の `y + h` ＋ 0.3 程度
2. `diagram_bottom` = `masterDecorations` の最小 `y` − 0.9 程度（要点行 2 行ぶんを残す）
3. `title_em_max` = `タイトル幅(pt) ÷ タイトルのフォントサイズ(pt)` × 0.95

設定したら `validate_layout.py` が通ることと、サムネイルで実際に崩れていないことの
両方を確認する。

## API 側の制約

- **要素のサイズを後から変えるリクエストが無い。** `updatePageElementTransform` は位置と
  スケールしか変えられない。既定レイアウト（`predefinedLayout`）のプレースホルダは
  幅が固定なので、タイトルを確実に 1 行に収めたい場合は
  テンプレートの `drawText` で座標指定のテキストボックスとして描く。
- `SLIDE_NUMBER` プレースホルダは生成できない。`add_page_numbers()` が自前で描く。
- 1 回の `batchUpdate` は 500 リクエスト程度で分割する（`commit(chunk_size=500)`）。
  図解 55 枚で約 6,000 リクエストになる。
- スピーカーノートの `objectId` はスライド作成後にしか分からないため、本体の
  `batchUpdate` 後に取り直して 2 回目を投げる（`commit()` が処理する）。
- 全面サイズの不透明な矩形はマスターのフッターを覆って消してしまう。
- **コネクタの端点がずれていても API はエラーにしない。** `createLine` は座標を
  そのまま受け取るだけで、図形との位置関係を検証しない。図形に紐づけたい場合は
  `updateLineProperties` の `startConnection` / `endConnection` を使う
  （`Canvas.connect()` が行う）。接続サイトは全シェイプ共通で 0=上 1=左 2=下 3=右。
