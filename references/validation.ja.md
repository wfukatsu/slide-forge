# 検証ゲート: オフライン座標チェックとサムネイル QA

生成した後に崩れを発見するのが最もコストの高い結果である。2 つのゲートが、
コストの異なる 2 段階で不具合を捕まえる。

1. **オフライン座標チェック** — 無料・即時・API 呼び出し無し。座標だけで
   証明できるものすべてを拾う: はみ出し、重なり、収まらない文字、外れた
   コネクタ、解決できないレイアウト。
2. **サムネイル QA** — 取得のたびに API を 1 往復、加えて人の目。座標では
   証明できないものすべてを拾う: 不自然な折り返し、他の図形を横切る矢印、
   **間違った**図形に繋がったコネクタ、弱いコントラスト、図が実際に伝えたい
   ことを伝えているか。

オフラインチェックは**生成前に毎回**実行する。サムネイル QA は
**`slide-qa` スキル**が所掌し、**生成時に実行するかどうかを選ぶ**（インテイクで
確認し、既定・推奨は実行）。実行する場合はゲート 2 の全体（取得・目視確認・
修正ループ・検証ファイルの削除〔`scripts/cleanup_qa.py`〕）をカバーする。
ユーザーがスキップした場合、デッキは未検証のまま納品され、報告にその旨を
明記しなければならない。どちらのゲートも他方の代わりにはならない。

すべてのコマンドはリポジトリルート（`/path/to/slide-forge`）から実行する。

---

## ゲート 1: オフライン座標チェック

どのコマンドを使うかはデッキの書き方による。

| デッキの形式 | コマンド |
|---|---|
| テンプレート駆動の JSON 仕様（このスキル） | `.venv/bin/python scripts/build_deck.py --template templates/<id>.json --spec deck.json --dry-run [--strict]` |
| `deckkit` で書いたコードファーストのデッキモジュール（`google-slides` スキル） | `.venv/bin/python scripts/validate_layout.py path/to/mydeck.py` |

どちらも API に触れずにすべての図形を座標へ展開し、同じ監査系
（`audit_bounds` / `audit_connectors` / `audit_overlaps` / `audit_text_fit`）を
実行する。`--dry-run` はさらに `template.json` に対するレイアウトの解決可否と
プレースホルダの整合性を検証する。`--strict` を付けると監査の警告が 1 件でも
あれば異常終了する — CI 的なゲートとして使える。

### validate_layout.py

```bash
.venv/bin/python scripts/validate_layout.py path/to/mydeck.py
.venv/bin/python scripts/validate_layout.py mydeck.py --template templates/my-brand.json
.venv/bin/python scripts/validate_layout.py mydeck.py --quiet    # silent when clean
```

問題が見つかると終了コード 1 を返すので、そのまま CI に組み込める。

### 何を検出するか

| チェック項目 | 何故失敗するか | 直し方 |
|---|---|---|
| 図が下端をはみ出す | マスターのロゴ、著作権表示、要点行のいずれかと衝突する | ブロックの高さと余白を詰める。`DY1` が図の下限 |
| 図が左右をはみ出す | スライドの外に出て見えなくなる | `X0`〜`XE` の内側に収める |
| タイトルが 2 行に折り返す | タイトルが `DY0` を越えて図と衝突する | 全角 30.5 文字以内に短縮する |
| 描画中の例外 | 座標計算のミス、部品への引数の誤り | トレースバックに従って直す |
| レイアウトが解決できない | ロール名の誤字、テンプレートにそのロールが無い | テンプレートの `roles` / `layouts` を確認する |
| プレースホルダが無い | レイアウトに TITLE/SUBTITLE/BODY が無い | 別のロールを使うか、`drawText` に対応したレイアウトを使う |
| コネクタがどの図形にも接していない | 両端がどの図形からも 0.22in 以上離れている | `d.connect(a, b)` / `d.link(a, b)` で図形を明示する |
| コネクタが図形の内部に埋まっている | 端点が図形の内部に 0.06in 以上入り込んでいる | 上記と同様。意図的な線であれば `free=True` を付ける |
| 文字が後の図形に隠れている | バナーやゾーンが前のブロックの上に描かれた | 各部品の戻り値（下端 y）を使って積み上げる |
| 文字どうしの衝突 | 塗りの無いラベルが、実際の文字が載る範囲で重なっている | 位置をずらす、文言を短くする |
| 枠に対して文字が多すぎる | 必要な行数が枠の高さを超えている | 枠を高くする、文字を減らす |

### 何を検出できないか（サムネイル QA が必要）

これらは座標からは見えない。必ず画像（ゲート 2）で確認すること。

- 不自然な折り返し（枠には収まっているが、助詞だけが単独で次行に落ちる）
- コネクタが**意味的に正しい**図形に繋がっているか（接続の有無は証明できるが、意味までは証明できない）
- 矢印が他の図形の上を横切っていないか（経路の良し悪しは判定されない）
- 矢印の向き・経路が意図した意味と一致しているか
- 色のコントラストが十分か
- 図が実際に伝えるべきことを伝えているか

### レイアウト契約（チェックの前提）

安全域は `deckkit` の定数で定義されている。既定値は 16:9（10 × 5.625in）
テンプレートでの実測値。

- `DY0 = 0.84` — 図を描き始めてよい上端（1 行のタイトルの下）
- `DY1 = 4.30` — 図を終えるべき下端
- `NY = 4.38` / `EY = 4.86` — 要点行・注記行（`foot()` が使う。チェックからは除外）
- `TITLE_EM_MAX = 30.5` — 1 行に収まるタイトル幅（全角換算文字数）

ページサイズが異なるテンプレートでは、デッキ側で上書きする。

```python
configure_layout(page_w=13.333, page_h=7.5, margin=0.6,
                 diagram_top=1.0, diagram_bottom=5.9,
                 note_y=6.0, edition_y=6.5)
```

`foot()` が描く要素は意図的に `DY1` より下にあり、チェックからは除外される
（`FOOT_MODE` フラグで制御）。下端固定の独自要素も同じ仕組みに乗せること。
詳細は `references/layout-contract.md`。

テンプレート駆動の JSON 仕様では、追加で手計算の見積もりが必要なことを
忘れないこと。API はプレースホルダの文字あふれを黙って受け入れるうえ、
`--dry-run` の `audit_text_fit` は `figures` しか調べない。本文の文字が
収まるかどうかは、このスキルの Phase 3 にある式で計算する
（段落間隔を含めること — 無視すると実際の収容量の約 6 割程度まで
見積もりが甘くなる）。

## ゲート 2: サムネイル QA（`slide-qa` スキル）

座標チェックははみ出し・重なり・文字収まり・コネクタの接続を拾う。
**座標から見えない不具合は依然として残る。** 生成時にユーザーが QA を
選んでいた場合（既定）は、生成後に画像を確認する。

```bash
.venv/bin/python scripts/fetch_thumbnails.py <URL or ID> --out out/qa --size LARGE
.venv/bin/python scripts/fetch_thumbnails.py <URL> --out out/qa --pages 3,8,12,20
```

`--size` は SMALL / MEDIUM / LARGE を受け付ける。判定には LARGE を使う。

デッキが 15 枚を超える場合は、QA をサブエージェントに分担させる
（`--pages 9-16` のように 6〜8 枚ずつ、指摘はテキストのみで返させる）—
`references/parallel-generation.md` を参照。

### どのページから開くか

理想はすべてのページを見ることだが、枚数が多いときは優先順位を付ける。

1. **要素数が最も多いページ**（重なりはここに最初に現れる）
2. **図が最も複雑なページ**（スイムレーン、分岐フロー、複数パネル）
3. **表があるページ**（行が増えると下方向にはみ出す）
4. **各章の最初のページ**（構成の読みやすさ）
5. 表紙、章扉、締めのページ（マスターの装飾と自前の描画の関係）

### チェックリスト

| 見る場所 | よくある不具合 | 直し方 |
|---|---|---|
| 箱の中の文字 | 1 文字だけ次行に折り返る（「〜へ」「〜出」など） | 文言を短くする。箱を広げる |
| タイトル | 2 行に折り返って図を覆う | 全角 30.5 文字以内に短縮する |
| 矢印の経路 | 接続はされているが、途中で別の図形を横切っている | 図形を並べ直す（縦積みにするなど）。audit では拾えない |
| 矢印の端点 | A→B のつもりが実際は A→C に繋がっている | audit は接続の存在しか証明しない。目で意味を確認する |
| パネルの幅 | 右端のパネルが狭すぎて文字が溢れる | 幅を配り直す。内容を下段の全幅カードへ移す |
| ラベル | 矢印や罫線に重なって読めない | 外側へ押し出す（`align` を START/END に） |
| マーカー（●・◆・棒）の隣のラベル | マーカーに文字が密着し、座標監査では見えない窮屈な縦間隔になっている | ボックス内で文字を縦方向に中央寄せする（`valign: MIDDLE`）。LARGE サイズで隙間を確認する |
| 表の列揃え | 短く均一な値（年、年月、ID）を左揃えにすると不揃いに見え、文章を中央揃えにすると散漫に見える | `aligns`: 短く均一な値は CENTER、数値は END、文章は START — プリミティブの既定（1 列目 START、以降 CENTER）が常に正しいとは限らない |
| 色 | 淡い背景に淡い文字でコントラストが弱い | `readable_on()` を使う。本文は 4.5:1 以上が必要 |
| フッター | 自分の描画がマスターのロゴ・著作権表示に重なっている | `DY1` より上に収める |
| 余白 | 図が上に寄って、下に大きな空白帯ができている | ブロックの高さを増やして縦の空間を使う |
| プレースホルダ | 文字が溢れている、または切れている。装飾が文字と衝突している | 文字を減らす、`bodyFontSize` や間隔を調整する、余裕のあるレイアウトを選ぶ |
| ページ番号 | 出ていない、または 2 桁で切れている | `add_page_numbers()` を確認する。位置を確認する |
| ロゴ・フッター | 二重に描かれている | 複製ではテンプレートの装飾が自動継承される — 自前の描画を削除する |
| レイアウトの系統 | Proposal 系と Presentation 系が混在している | 仕様の `layout` の値を直す |

### 目を細めるテスト

目を細めて（あるいは SMALL サムネイルで）見る。**最初に目に入るのは、
そのページの伝えたいメッセージか？** そうでなければ、強調（塗り・太字・色）
のかけ方が間違っている。

## 修正ループ

```
fetch thumbnails → identify defects → fix the spec / deck module
  → offline check (free) → regenerate → re-fetch only the affected pages → confirm
```

- 再生成は常に新しいプレゼンテーションを作る。**差し替え前のバージョンは
  Drive のゴミ箱に移す**（残しておくとどれが最新か分からなくなる）。
  ユーザーが保持する URL は常に 1 つ（最新のもの）にする。
- 生成済みの成果物をその場で直接編集しない。仕様やモジュールを直して
  再ビルドする方が速く、再現性もある。
- 部分レンダリング（`render_deck.py --only 3-8`、コードファースト経路）は
  反復作業中のクォータと待ち時間を節約するが、ページ番号がずれるので、
  最終確認はフル実行で行う。
- 検証中に作成した中間デッキは Drive から削除する
  （`drive.files().delete(fileId=…)`）。

## QA ファイルの後片付け（必須）

サムネイルは検証のためだけに存在し、いつでも再取得できる。QA が終わったら
—— 合格・不合格から修正済み・中断のいずれであっても —— 報告の前に削除する。

```bash
.venv/bin/python scripts/cleanup_qa.py            # removes out/qa, out/qa-*, out/*/qa
.venv/bin/python scripts/cleanup_qa.py --dry-run  # preview the targets
.venv/bin/python scripts/cleanup_qa.py out/mydeck/qa   # a specific directory
```

このスクリプトは `out/` の外にあるものには手を出さない（すべて gitignore
済み）ので、無条件に実行してよい。

## 報告のルール

- 直したものについては、**何が間違っていて、どう直したか**を明記する。
  「直しました」だけでは検証できない。
- 直さなかったものについては、直していないと明示する。
- 掲載した数値・グラフには出典を示す。出典の無い数値はスライドに載せない。
- 結果を提示する前に自分で QA に合格しておく — 目視すれば分かる不具合を
  ユーザーに見つけさせない。
