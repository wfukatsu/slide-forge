# スラッシュコマンド

プラグインには 3 つのコマンドが同梱されている。多くの人が実際に使う入口はここで、
コマンドがスキルへ振り分けるため、**始める前に 24 スキルのどれが適切かを知っている
必要はない**。

| コマンド | 引数 | 何が出てくるか |
|---|---|---|
| `/forge` | テーマ、テンプレート URL、資料のパス、顧客名など | デッキ 1 本（最初から最後まで） |
| `/account` | `<顧客名> [new \| update \| show] [議事録のパス]` | 顧客の活動計画。**URL は変わらない** |
| `/visit` | `<顧客名> [目的 / 相手 / フェーズ] [議事録のパス]` | 1 回の訪問の資料一式。Drive に格納 |

Claude Code では `/forge`・`/account`・`/visit`（マーケットプレイス導入時は
`/slide-forge:forge`）。Codex では `forge` スキルを名前で呼び出す。`/account` と
`/visit` は Claude Code のコマンドである。3 つとも
[workflow-contract.md](workflow-contract.ja.md) に従う。

## `/forge` — デッキ生成

生成スキルをちょうど 1 つ選び、インテイク → アウトライン承認 → 仕様 → オフライン検証
→ 生成 → 任意の視覚 QA → 後片付け → 任意の PPTX・スプレッドシート → 報告、までを走らせる。

スキルは引数から選ばれ、本当に判断がつかないときだけ 1 度質問する。振り分け表は
[`commands/forge.md`](../commands/forge.ja.md) にある。要約すると、Scalar の製品デッキ、
課題起点の提案、分析フレームワーク、カレンダー、B2B のステークホルダーマップ、
情報を集めるためのスライド、nexus-architect の説明には、それぞれ専用のスキルがある。
それ以外は、マスターがあれば `google-slides-template`、無ければ `google-slides` に落ちる。

**アウトライン承認は必須のゲートである。** ページ数・レイアウト・アクションタイトルを
承認した後は、納品まで再確認を挟まずに進む。

## `/account` — 顧客の活動計画

顧客の台帳を読み、直近のミーティングで分かったことを記録し、プレイブックの 10 の
レビュー質問を照合し、未回答のものをすべて「誰に聞くか・期限」付きのアクションに変え、
同じ活動計画デッキの中身を差し替える（共有リンクはそのまま使い続けられる）。

**台帳が答えられないことが、そのまま成果物になる。** 黙って落とさない。

## `/visit` — 1 回の訪問の資料

商談フェーズ × 相手 × 目的で資料タイプへ振り分け、顧客提示のワンページャー・社内向け
訪問計画・ウィンプラン・稟議パケットが同じファイルにならないようにする。特定個人への
評価、競合の弱点、未確認の数字が顧客の目に触れるものへ混ざらないことを確認したうえで、
各成果物を生成・格納し、訪問結果を台帳へ書き戻して活動計画を更新する。

## 状態の置き場所

`/account` と `/visit` の正本は `accounts/<AE 名>/<顧客名>/account.json` にあり、
gitignore 対象でコミットされない。出力は `<Drive ルート>/<AE 名>/<顧客名>/` 配下に
格納する。Drive ルートは最初に一度だけ聞かれ、`config/sales.json` に記憶される。
