# サムネイルによる視覚 QA

座標検査は、はみ出し・重なり・文字溢れ・コネクタの接続まで拾う。それでも
**座標だけでは分からない不具合が残る。** 生成したら必ず画像を見る。

```bash
python <plugin>/scripts/fetch_thumbnails.py <URL または ID> --out out/qa --size LARGE
python <plugin>/scripts/fetch_thumbnails.py <URL> --out out/qa --pages 3,8,12,20
```

`--size` は SMALL / MEDIUM / LARGE。判定には LARGE を使う。

## 何を見るか

### 優先して開くページ

全ページ見るのが理想だが、枚数が多いなら次を先に見る。

1. **要素数が最も多いページ**（重なりが出やすい）
2. **図が最も複雑なページ**（スイムレーン、分岐フロー、複数パネル）
3. **表があるページ**（行が増えて下にはみ出しやすい）
4. **章の 1 ページ目**（構成の見え方を確認）
5. 表紙・中扉・裏表紙（マスターの装飾と自分の描画の衝突）

### チェック項目

| 見るところ | よくある不具合 | 直し方 |
|---|---|---|
| 箱の中の文字 | 1 文字だけ次行に落ちる（「〜へ」「〜出」） | 文言を短くする。箱を広げる |
| タイトル | 2 行になって図に被る | 30.5 全角文字以内に短くする |
| 矢印の経路 | 接続はしているが、途中で別の図形を横切っている | 図形の並びを変える（縦積みにする等）。検査器では拾えない |
| 矢印の接続先 | A→B のつもりが A→C に繋がっている | 検査器は接続の有無しか見ない。意味は目で確かめる |
| パネルの幅 | 右端のパネルが狭くて文字が溢れる | 幅を配り直す。下段の全幅カードに移す |
| ラベル | 矢印や罫線と重なって読めない | 外側に寄せる（`align` を START/END に） |
| 色 | 淡い背景に淡い文字でコントラスト不足 | `readable_on()` を使う。通常テキストは 4.5:1 以上 |
| フッター | マスターのロゴ・著作権と自分の描画が重なる | `DY1` より上に収める |
| 余白 | 図が上に寄って下が大きく空く | ブロックの高さを増やして縦を使い切る |

### スクイントテスト

目を細めて（または SMALL サムネイルで）見る。**最初に目に入るものが、そのページの
一番言いたいことになっているか。** なっていなければ、強調（塗り・太字・色）が間違っている。

## 修正のループ

```
サムネイル取得 → 不具合を特定 → デッキモジュールを直す
  → validate（無料）→ 再生成 → 該当ページだけ再取得して確認
```

再生成は毎回新しいプレゼンテーションを作る。**差し替え前の版は Drive のゴミ箱に移す**
（消さずに残すと、どれが最新か分からなくなる）。ユーザーに渡した URL は最新の 1 つだけにする。

部分生成（`render_deck.py --only 3-8`）で試すとクォータと待ち時間を節約できるが、
ページ番号が変わるので最終確認は通しで行う。

## 報告するとき

- 直したものは「何が起きていて、どう直したか」を書く。「修正しました」だけでは検証できない。
- 直していないものは、直していないと明記する。
- 数値やグラフを載せた場合は出典を示す。出典が無い数値は載せない。
