# 図解デッキの生成

デッキは **1 モジュール = 1 デッキ**の Python ファイルとして書く。関数がスライド 1 枚に対応し、
図は `diagrams.Canvas` のプリミティブで描く。生成前に必ずオフラインの座標検査を通す。

```
調査・構成設計 → デッキモジュールを書く → 座標検査（無料・即時） → 生成 → サムネイル目視
                                              ↑____________修正____________|
```

## 手順

### 1. テンプレートを決める

| 状況 | 使うもの |
|---|---|
| 自社マスターがある | `template` スキルで解析・登録して `templates/<name>.json` を作る |
| マスターが無い / まず試す | 同梱の `templates/blank-16x9.json`（新規プレゼンを作る） |

マスターを複製する場合、装飾・ロゴ・著作権フッターはレイアウトから自動継承される。
**これらを自分で描いてはいけない**（二重描画になる）。

### 2. 構成を決める

- **1 スライド = 1 メッセージ**。タイトルは結論文（アクションタイトル）にする。
  ラベル型（「〜について」「〜の概要」）は禁止。
- タイトルは **1 行に収める**。全角換算で 30.5 文字が上限（`deckkit.em()` で測れる）。
  2 行になるとタイトルが図の領域を侵食する。検査で落ちる。
- 章が 4 つ以上になるなら中扉（SECTION）を挟む。
- 各ページの下部は `foot(d, ["要点1行"], "補足行")` で揃える。書式が一定だと読みやすい。

### 3. デッキモジュールを書く

```python
import json, os, sys
sys.path.insert(0, "<plugin>/scripts")
from deckkit import *

TITLE = "デッキのタイトル"
TEMPLATE = json.load(open("<plugin>/templates/blank-16x9.json", encoding="utf-8"))

plain(layout="COVER", title="タイトル", subtitle="サブタイトル")
plain(layout="SECTION", title="1. 章タイトル", body="この章で何を示すか")

@slide("Consensus Commit が DB 横断で ACID を成立させる", note="スピーカーノート")
def s_overview(d):
    layers(d, X0, DY0, W, [
        ("アプリ", "業務アプリケーション", d.P.primary),
        ("基盤",   "ミドルウェア",         d.P.primaryDark),
    ])
    banner(d, DY1 - 0.4, "この構成の要点", tone="good")
    foot(d, ["・持ち帰ってほしい1行"], "提供: ... ｜ 状況: GA")
```

描画関数の引数 `d` は `Canvas`。座標は**すべてインチ**、原点はスライド左上。
使えるパーツと図のパターンは `references/diagram-cookbook.md` を読む。
座標の安全域と実測値は `references/layout-contract.md` を読む。

### 4. 座標を検査する（省略禁止）

```bash
python <plugin>/scripts/validate_layout.py mydeck.py
```

API を呼ばないので無料・即時。次を検出する。

- 図がフッター領域（`DY1`）に侵入 → マスターのロゴ・要点行と重なる
- 図がスライドの左右外に出ている
- タイトルが 2 行になる → 図と重なる
- 描画中の例外（座標計算のミス）
- レイアウト名が解決できない / 存在しないプレースホルダを指定している
- コネクタの端点がどの図形にも接していない / 図形に埋まっている
- **文字が後から描いた図形に隠れている**（バナーやゾーンが直前のブロックに重なった）
- **ラベルどうしが実際の文字の範囲でぶつかっている**
- **枠に対して文字が多すぎる**（溢れた文字は切れて見える）

**0 件になるまで直す。** ここを通さずに生成すると、Drive にゴミが増えるだけで何も分からない。

### 5. 生成する

```bash
python <plugin>/scripts/render_deck.py mydeck.py --title "タイトル" [--folder <URL/ID>]
python <plugin>/scripts/render_deck.py mydeck.py --only 1-12    # 部分生成で見た目を試す
python <plugin>/scripts/render_deck.py mydeck.py --dry-run      # 構成の一覧だけ
```

`render_deck.py` は生成前に検査を自動実行し、問題があれば生成しない。

### 6. サムネイルで目視する（省略禁止）

`qa` スキルの手順に従う。検査は座標しか見ないので、**文字の不自然な折り返し・矢印の向き・
図の意味の通り方は画像を見ないと分からない**。密度の高いページと図が複雑なページを必ず開く。

## 図を選ぶ

| 伝えたいこと | 使う関数 |
|---|---|
| 現状の問題 → 解決後、A / B | `compare_panels` |
| 誰が何をするか | `swimlane` |
| 時系列・期間・重要な時点 | `timeline` |
| 工程の流れ（担当範囲を強調） | `pipeline` |
| 番号つきの手順 | `steps_v` |
| 階層・責務の分担 | `layers` |
| 親子関係・構造 | `tree` |
| 土台 → 応用 ／ 母数 → 結果 | `pyramid` ／ `funnel` |
| 閉じた繰り返し | `cycle` |
| 条件分岐 | `decision` |
| 優先度の4象限 ／ 2軸の位置づけ | `quadrant` ／ `matrix_map` |
| フェーズ × レーンの計画 | `roadmap` |
| 中央の対象への注釈 | `callouts` |
| 対応表・可否 | `grid`（`cell_colors` で色分け） |
| 順序のない列挙 | `pills` |
| 状態つきの確認項目 | `checklist` |
| 大きな数値（出典がある場合のみ） | `stats` |
| 色の意味 | `legend` |
| データの所在 | `db`（円柱アイコン） |

全 32 種の早見表と呼び出し例は `references/diagram-cookbook.md`。
描画済みの見本は `examples/pattern-gallery/`。

**すべてのパターンは戻り値に下端 y を返す。次のブロックはその値を起点に置く。**
手で `DY0 + 2.7` のような値を書かない。内容が増えたとき下のブロックへ潜り込む。

```python
b = compare_panels(d, X0, DY0, W, 2.90, left, right)
banner(d, b + 0.16, "まとめの一行", tone="good")
foot(d, ["・持ち帰ってほしい1行"])
```

**やってはいけないこと**

- 実測していない性能数値をグラフにする。数値は出典があるものだけ。
  無い場合は「変えるべき変数」など構造を図にする。
- **図形どうしを結ぶ矢印の座標を手で書く。** `d.connect(a, b)`（API で接続・追従する）か
  `d.link(a, b)`（辺の交点を端点にする）を使う。端点がずれていても API はエラーにしない。
  軸や引き出し線など figure に接しないのが正しい線は `d.line(..., free=True)` と明示する。
- レーンをまたぐ矢印を水平に引く（経路が嘘になる）。始点と終点の実座標を結ぶ。
- 0.1in 未満の矢印。短すぎて描画されず、ゴミのように見える。0.12in 以上にする。
- マスター由来のロゴ・フッターを自分で描く。
- 全面サイズの不透明な矩形。マスターのフッターを覆って消す。
- 箱の高さに対して固定比率で中身を割り当てる。箱が小さいと中身が潰れて文字が切れる。
  自作の部品は与えられた領域に収まるよう自分で縮ませる。

## 資格情報

`credentials.json`（Google Cloud の OAuth 2.0 デスクトップクライアント）を
`~/.config/slide-forge/` に置く。Slides API と Drive API を有効化しておく。
初回実行時にブラウザで認証し、`token.json` が自動生成される。
配置場所は環境変数 `SLIDE_FORGE_CONFIG_DIR` で変更できる。

依存パッケージは `<plugin>/requirements.txt`。venv での実行を推奨。
