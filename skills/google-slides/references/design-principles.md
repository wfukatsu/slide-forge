# スライドデザイン原則 クイックリファレンス

> McKinsey / BCG / Reynolds / Duarte / Tufte の包括的合成。定量基準と実践ルールに集中。

---

## 1. レイアウト

### グリッドシステム

- アスペクト比: **16:9**（Google Slides: 10" x 5.625"）
- 左右マージン: 最低 0.5"（推奨 0.75"〜1.0"）
- 上下マージン: 最低 0.5"
- 全要素はマージン内に収まること（はみ出し禁止）

### 3層構造（コンサルティング標準）

| 層 | 位置 | 内容 |
|----|------|------|
| タイトル層 | 上部 15-20% | アクションタイトル（結論文） |
| 本体層 | 中央 60-70% | チャート、テーブル、テキスト、図 |
| フッター層 | 下部 5-10% | ソース出典、ページ番号 |

### 視覚的階層

- フォントサイズの差異（見出し > 小見出し > 本文）
- ウェイトの差異（Bold > Regular > Light）
- 色のコントラスト（アクセント色 > 主色 > 補助色）
- 配置の優先度（上部・左部 > 下部・右部）

### ホワイトスペース

- スライド全面積の **最低15%** をホワイトスペースとして確保
- 要素間の最小間隔: **0.15"**
- マクロ（大要素間）とミクロ（行間・段落間）の両方を意識する

### ゲシュタルト原則

| 原則 | スライドでの適用 |
|------|----------------|
| 近接 | 関連情報を物理的に近くに配置 |
| 類似 | 同カテゴリの要素に同じ色・形・サイズ |
| 整列 | 全要素をグリッドに沿って整列 |
| 連続 | 左上→右下の読み順を活用 |
| 図と地 | 前景と背景に十分なコントラスト |

## 2. タイポグラフィ

### フォントサイズ（3パターン）

**キーノート（ライブ発表）:**

| 要素 | 最小 | 推奨 |
|------|------|------|
| メインタイトル | 36pt | 44-60pt |
| サブタイトル | 28pt | 32-36pt |
| 本文 | 24pt | 28-48pt |

**営業/トレーニング資料（送付・共有）:**

| 要素 | 最小 | 推奨 |
|------|------|------|
| タイトル | 20pt | 28pt+ |
| ヘッダー | 16pt | 20pt+ |
| 本文 | 12pt | 16pt+ |

**コンサルティングデッキ（McKinsey基準）:**

| 要素 | サイズ |
|------|--------|
| アクションタイトル | 24-28pt（Bold、最大2行） |
| サブヘッディング | 18-20pt |
| 本文 | 16-18pt |
| チャートラベル | 12-14pt |
| フッター/ソース | 10-12pt |

### 日本語タイポグラフィ

- **行間**: フォントサイズの **185-200%**（欧文は130-150%）
- **1行あたり最適文字数**: 約 **30-35文字**
- 推奨フォント: Noto Sans JP、メイリオ、ヒラギノ角ゴ Pro
- ラテン文字混植: Noto Sans JP + Noto Sans（または Arial）

### フォントペアリング

- **セリフ + サンセリフ** の組み合わせが最も安全
- 1プレゼンテーションで **最大2〜3書体** に限定
- 類似しすぎるフォント同士は避ける（コントラスト不足）

### 可読性ルール

- スクリーン本文: **サンセリフ体** を推奨（Arial, Calibri, Noto Sans）
- テキスト配置: **左揃え**（スキャン性最高）
- 強調: **Bold のみ**（Italic は技術用語のみ、下線・影・装飾フォントは禁止）
- **3秒ルール**: 聴衆が3秒以内に把握できなければ情報過多

## 3. カラー

### 60-30-10 ルール

| 比率 | 役割 | スライドでの適用 |
|------|------|----------------|
| 60% | 基調色 | 背景色（白/ライトグレー）+ 本文テキスト |
| 30% | 補助色 | 構造要素、サブヘッダー、チャートの主色 |
| 10% | アクセント色 | キーデータの強調、CTA、重要な数値 |

- 1スライドの色: **最大3色**（上限5色）
- アクセント色は希少性が重要。使いすぎると効果を失う

### WCAG コントラスト比

| レベル | 通常テキスト | 大テキスト(18pt/14ptBold+) | 非テキスト要素 |
|--------|------------|--------------------------|-------------|
| AA（必須） | **4.5:1** 以上 | **3:1** 以上 | **3:1** 以上 |
| AAA（推奨） | 7:1 以上 | 4.5:1 以上 | -- |

- 色だけに依存して情報を伝えない（色覚異常への配慮）
- チャートでは色に加えてパターン・ラベルを併用

### セマンティックカラー

デッキ全体でカラーの意味を統一する:

| 意味 | 色 |
|------|-----|
| 自社製品 | ブルー系（primary） |
| 外部/既存 | グレー系（secondary） |
| ユーザー/クライアント | オレンジ系（tertiary） |
| 正常フロー/成功 | 緑 |
| エラー/失敗 | 赤 |
| 注意/新機能 | 黄 |

### 背景色の使い分け

| 背景タイプ | 使用場面 | 使用頻度 |
|-----------|---------|---------|
| ソリッドホワイト | 通常コンテンツ | **80%以上** |
| ダークブルー/ネイビー | 表紙、セクション区切り、結論 | 限定使用 |
| ライトグレー | ハイライトスライド | 限定使用 |
| 写真背景 | **非推奨** | 不使用 |

## 4. コンテンツ密度

### 1スライド = 1メッセージ（最重要原則）

すべての権威ある情報源が一致して推奨する原則:
- Reynolds: 「スライドは文書ではない。1つのビジュアルメッセージに限定」
- Duarte: 「聴衆はスライドの文字を読みながら話を聞くことはできない」
- McKinsey: 「1スライドに1つのアクションタイトル。本体はその根拠」

### Miller's Law（情報チャンキング）

ワーキングメモリ容量は **7 +/- 2**（近年の研究では **4チャンク**）:
- 箇条書き: **最大6項目**（推奨5以下）
- カテゴリ/グループ: **3〜5個**
- セクション数: **3〜5**
- ネストレベル: **最大2階層**

### テキスト制約

| 要素 | 日本語 | 英語 |
|------|--------|------|
| 表紙タイトル | 16文字 | 40文字 |
| アクションタイトル | 50文字 | 100文字 |
| ブレット項目 | 40文字 | 80文字 |
| 1行推奨 | 20文字 | 5語 |
| スピーカーノート | 200文字 | 400文字 |

### 連続性ルール

- テキスト多めスライドは **5枚連続しない**（チャート/図を挟む）
- セクションディバイダはデッキ全体の **10-15%** に抑える

## 5. アクションタイトル原則

### ラベル型 vs 結論型

**ラベル型（NG）:**
- 「製品概要」
- 「ベンチマーク結果」
- 「認証・認可」

**結論型 = アクションタイトル（OK）:**
- 「ScalarDB は異種DB間のHTAPを統合するミドルウェアである」
- 「異種DB間でもACIDを保証し、既存DBの変更は不要」
- 「DB非依存の統一セキュリティレイヤを提供」

### アクションタイトルの書き方

1. **結論を先に**（ピラミッド原則）: 本体はタイトルの根拠
2. **「だから何？（So What?）」テスト**: タイトルに「だから何？」と聞いて答えが出ないならラベル型
3. **動詞または結論を含む**: 「〜を実現」「〜を保証」「〜により〜が可能」

### ストーリーラインテスト

デッキのすべてのアクションタイトルを順に並べて読んだとき:
- **論理的な流れ** が理解できること（課題→解決→効果）
- 技術的な「何」だけでなく、ビジネス的な **「なぜ」** が含まれること
- 意思決定者が **タイトルだけで判断に必要な情報を得られる** こと

### ピラミッド原則（SCR フレームワーク）

```
結論（先に） → 根拠1 + 根拠2 + 根拠3（MECE） → 詳細データ
```

**エグゼクティブサマリー（SCR）:**
- **S**ituation（状況）: 聴衆が同意する背景
- **C**omplication（課題）: 緊張感を生む問題
- **R**esolution（解決策）: 提案とその効果

## 6. データビジュアライゼーション

### チャート選択ガイド

| データの目的 | 推奨チャート | 非推奨 |
|-------------|------------|--------|
| カテゴリ比較 | 横棒グラフ | 3D棒、レーダー |
| 時系列トレンド | 折れ線（5-6本以下） | 面グラフ（重なり不明瞭時） |
| 構成比 | 積み上げ棒 | 円グラフ（5カテゴリ超） |
| 相関関係 | 散布図 + トレンドライン | -- |
| 増減フロー | ウォーターフォール | -- |

### Tufte の原則

**Data-Ink Ratio（データインク比）を最大化:**
- グリッドライン、枠線、装飾的要素は可能な限り除去
- データラベルを直接配置（凡例の代わり）

**Lie Factor = 1 を目標:**
- グラフィック上の変化率 = 実際のデータ変化率

**チャートジャンクの排除:**
- 3D効果、影、グラデーション、装飾要素は禁止
- グリッドラインは除去または極薄グレー

### チャートデザインルール

- 1チャート = 1メッセージ
- 棒グラフ/柱状グラフの **ゼロベースライン厳守**
- 円グラフは **3-5カテゴリまで**（6超は禁止）
- ソース出典をフッターに記載
- コールアウトボックスでキーインサイトを強調
- 1チャートの色: 最大3色（比較チャートでも5色まで）

## 7. アンチパターン

### コンテンツ

| アンチパターン | 解決策 |
|-------------|--------|
| テキスト過剰 | 1スライド1メッセージ。テキスト最小限 |
| 箇条書きの乱用 | ビジュアル表現優先。チャート/図/アイコン活用 |
| スライドの文書化 | 配布資料は別途作成（スライドゥメント禁止） |
| 物語の欠如 | SCR/ピラミッド原則を適用 |
| ラベル的タイトル | アクションタイトル（結論文）に変更 |

### ビジュアル

| アンチパターン | 解決策 |
|-------------|--------|
| 色の使いすぎ（レインボー） | 60-30-10ルール。最大3色 |
| 過度なアニメーション | 最小限。遷移は2-3種に統一 |
| テンプレート不統一 | マスタースライドで全体統一 |
| 低品質画像 | 高解像度のみ。アスペクト比維持 |
| 装飾過多 | フラットデザイン。ホワイトスペース活用 |

### チャート

| アンチパターン | 解決策 |
|-------------|--------|
| 3Dチャート | 2Dのみ使用 |
| ゼロベースライン欠如 | 棒グラフは必ずゼロ始点 |
| 多すぎるカテゴリ | 円グラフは3-5まで。超過は棒グラフ |
| 凡例への依存 | データラベルを直接配置 |
| チャートジャンク | Data-Ink Ratio を最大化 |

## 9. インフォグラフィクスデザイン

### フォントサイズ下限（パターン共通）

> パターン固有のフォントサイズ詳細は `infographic-patterns.md` の「フォントサイズ最小基準」セクションを参照。

| 要素 | 最小 | 推奨 |
|------|------|------|
| パターンタイトル | 14pt | 16pt+ |
| ラベル（軸・凡例） | 10pt | 12pt |
| サブラベル（補足説明） | 10pt | 10pt |
| 統計数値（大数字） | 20pt | 24pt+ |
| バッジ内テキスト | 10pt | 12pt |

### テキスト折り返し防止

列幅に応じた文字数上限を厳守する:

| 列幅 | 日本語上限 | 英語上限 |
|------|-----------|---------|
| 1.0" 以下 | 5文字 | 8文字 |
| 1.0"〜1.5" | 8文字 | 15文字 |
| 1.5"〜2.0" | 12文字 | 20文字 |
| 2.0" 以上 | 16文字 | 30文字 |

日英混在テキスト（例: 「ACIDトランザクション」）は英字部分が折り返し不可のため、同じ列幅でも文字数が少なくなる点に注意。

### カラー使用ルール

**フロー図**: 同系色のグラデーション（例: 淡い→濃いブルー）で進行を表現。工程ごとに無関係な色を使わない。分岐・検証ノードは補色（例: ティール）で差別化。

**ドーナツ/円グラフ**: 同一色相の濃淡ではなく、**異なる色相**（例: ネイビー・ティール・パープル・ライトブルー）で各セグメントを区別する。

**アイコンバッジ**: 1スライド内のアイコンバッジ色は `C.primary` に統一。機能差別化には色ではなくテキスト・アイコンを使う。

**注意色（caution）**: 金色 `#BE9000` は白背景でコントラスト比 2.8:1 のため、テキストには使用禁止。ラベル用に `cautionDark #6B5000`（7:1+）を使う。

### コンポーネント固有ルール

**統計カード**: アクセントバー（上部カラーバー）は**不要**。ボーダー線のみでカードを差別化する。バッジ円も不要（視覚ノイズ）。値は `24pt Bold`、ラベルは `10pt` 以上。

**比較カード**: カード高さはブレット数 × 0.45" + ヘッダー 0.50" を目安に算出。過大な余白を避ける。タイトルは `15pt` 以上。

**テーブルヘッダー**: `header_fill`（色付き背景）を使用するテーブルでは、ヘッダー行のテキストに**必ず白色太字**（`text_style(10, True, C.WHITE, "Arial")`）を適用する。背景色のみでテキスト色を変更しないと、デフォルトの黒文字が色付き背景上で読みにくくなる。

**コネクタは必ず図形に接続する**: 座標直指定（`add_connector`）で図形どうしを結ばない。
Slides API は線の座標をそのまま受け取り、図形との位置関係を検証しないため、端点が
ずれていてもエラーにならない。「矢印が図形から浮いている」「枠に食い込んでいる」は
生成してサムネイルを見るまで気づけない不具合になる。図形どうしは
`add_connected_connector`（`startConnection` / `endConnection`）で結ぶ。座標直指定は
経路の折れ点・軸・引き出し線など、図形に接しないのが正しい線にのみ使う。

**コネクタタイプ**: シェイプ接続コネクタ（`add_connected_connector`）は**BENT（エルボー）をデフォルト**とする。直線コネクタ（STRAIGHT）は垂直/水平の直接接続（例: アプリ→DB の1対1接続）にのみ使用する。BENT はファンアウト（1対多接続）で経路が交差せずプロフェッショナルな外観になる。

**セクションディバイダのページ番号**: テキストボックス幅は**0.5" 以上**にすること。0.264" では2桁ページ番号（"18"、"26" 等）が1文字ずつ折り返される。

**Closing スライドのテキストコントラスト**: サブタイトル・連絡先テキストは `#666666` 以上の濃さにすること。`#888888`（コントラスト比 ~3.5:1）は白背景で WCAG AA を満たさない。

**暗色背景カードのラベル**: 暗色背景（ダークブルー/ネイビー）上の白半透明カード内のラベルテキストは、**12pt Bold 以上**にし、alpha を **0.30 以上**に設定すること。alpha 0.25 以下ではラベルのコントラストがボーダーラインになる。

**カードのアクセントバー**: カード上部の細いカラーバー（`add_rect` で 0.025" 高さ）は**使用しない**。ボーダー色やヘッダー背景色でカード間の差別化を表現する。アクセントバーは視覚的にノイズとなり、クリーンなカードデザインを損ねる。

**タイトルスライド**: 見出しは幾何学的中心ではなく**光学的中心**（y = スライド高さ × 0.33）に配置する。

**プログレスバー**: ラベルフォントサイズは `max(int(h * 40), 10)` で算出（最小 10pt）。

### 半透明カードオーバーレイ

暗色背景（ダークブルー/ネイビー）上の白い半透明カードは、`shape_opacity()` の alpha 値が低すぎるとカードが視認できない。

| 用途 | 最低 alpha | 推奨 alpha |
|------|-----------|-----------|
| 暗色背景上の白カード | **0.20** | 0.25-0.30 |
| 白背景上の薄色カード | 0.05 | 0.08-0.15 |
| ベン図の重複表現 | 0.30 | 0.40 |

> **注意**: alpha 0.15 は暗色背景ではほぼ不可視になる。KPI ハイライト、ROI インパクト、サマリーカード等で白カードを使用する場合は必ず **0.20 以上** を設定すること。

### 棒グラフの値ラベル

**縦棒グラフ**: 値ラベルのバー上方オフセットは **0.30" 以上**（0.22" ではバーと重なる）。テキストボックス高さは 0.25"。

**横棒グラフ**（`add_bar_chart` horizontal モード）の値ラベルは、テキストボックス幅不足による折り返しが発生しやすい。

- テキストボックス幅: **0.9" 以上**（0.5" では "50,000" 等で折り返す）
- 数値フォーマット: カンマ区切り（`f"{value:,}"`）で可読性を向上
