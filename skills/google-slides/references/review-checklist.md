# デザインレビューチェックリスト

> スライドデッキの定量的・視覚的品質を評価するフレームワーク。
> 基準: `design-principles.md` の定量ガイドライン。

---

## 1. 評価カテゴリ

| # | カテゴリ | ウェイト | 評価対象 |
|---|---------|---------|---------|
| 1 | レイアウト一貫性 | 20% | グリッド準拠、タイトル/フッター位置統一、マージン、コネクタが図形に接続しているか、文字が他の図形に隠れていないか |
| 2 | タイポグラフィ | 20% | フォントサイズ基準、書体統一、行間、可読性 |
| 3 | カラー使用 | 15% | 60-30-10、WCAG コントラスト比、セマンティック統一 |
| 4 | コンテンツ密度 | 20% | 1スライド=1メッセージ、箇条書き数、テキスト量 |
| 5 | ビジュアルストーリーテリング | 15% | アクションタイトル、ストーリーライン、図解/チャート活用 |
| 6 | アクセシビリティ | 10% | コントラスト比、フォントサイズ最小基準、色依存度 |

**総合評価:** A（90+）/ B（75-89）/ C（60-74）/ D（60未満）

## 2. 定量チェックリスト

### フォントサイズ

| チェック項目 | パス基準 | フェイル基準 |
|------------|---------|------------|
| 本文テキスト（送付資料） | >= 12pt | < 12pt |
| 本文テキスト（キーノート） | >= 24pt | < 24pt |
| タイトル（送付資料） | >= 20pt | < 20pt |
| 著作権/ページ番号 | >= 7pt | < 7pt |
| ソース出典 | >= 10pt | < 10pt |
| フォント種類数 | <= 3種 | > 3種 |

### コントラスト比

| チェック項目 | パス基準 | フェイル基準 |
|------------|---------|------------|
| 通常テキスト on 背景 | >= 4.5:1 (WCAG AA) | < 4.5:1 |
| 大テキスト(18pt+) on 背景 | >= 3:1 (WCAG AA) | < 3:1 |
| 非テキスト要素 on 背景 | >= 3:1 | < 3:1 |

### 重なり・文字溢れ

生成前に座標で確認できる。ここを飛ばすと、サムネイルを見るまで気づけない。

| チェック項目 | パス基準 | フェイル基準 |
|------------|---------|------------|
| 後から描いた図形が文字を覆っていないか | 覆っていない | バナー・ゾーンが直前のブロックに重なる |
| ラベルどうしの重なり | 文字の実範囲で重ならない | 文字が重なって読めない |
| 枠に対する文字量 | 必要行数 × 行高 <= 枠の高さ | 枠から溢れて切れる |
| 箱の中身の割り当て | 箱が小さくても中身が縮んで収まる | 固定比率で割り当てて潰れる |

### コンテンツ密度

| チェック項目 | パス基準 | フェイル基準 |
|------------|---------|------------|
| 箇条書き数/スライド | <= 6（推奨5以下） | > 6 |
| テキスト連続スライド | <= 5枚 | > 5枚連続 |
| 1行あたり文字数（日本語） | 20-40文字 | > 40文字 or 不自然な折り返し |
| セクションディバイダ比率 | <= 15% | > 20% |
| ネストレベル | <= 2階層 | > 2階層 |

### カラー

| チェック項目 | パス基準 | フェイル基準 |
|------------|---------|------------|
| 1スライドの色数 | <= 3色（上限5） | > 5色 |
| 白背景スライド比率 | >= 80% | < 70% |
| セマンティックカラー統一 | 全スライドで一貫 | スライド間で不統一 |

## 3. レビュー手順（4ステップ）

### Step 1: サムネイル俯瞰

全スライドのサムネイルを一覧表示し、以下を確認:
- デッキ全体の **視覚的リズム** （単調な箇条書きが連続していないか）
- セクションディバイダの **適切な配置と頻度**
- カラーの **一貫性** （突然異なる配色のスライドがないか）
- レイアウトの **統一感** （タイトル位置、フッター位置）

### Step 2: ストーリーラインテスト

全スライドのタイトルだけを順に読み、以下を確認:
- **論理的な流れ** があるか（課題→解決→効果）
- **アクションタイトル** になっているか（ラベル型ではなく結論型）
- タイトルだけで **意思決定に必要な情報** が得られるか
- ビジネス的な **「なぜ」** が含まれているか

### Step 3: 個別スライドチェック

各スライドに対して定量チェックリスト（セクション2）を適用:
- フォントサイズの最小基準
- コントラスト比
- 箇条書き数とテキスト量
- カード内の空白率（55%超は過大）
- テキストの折り返し（不自然な1文字折り返しがないか）

### Step 4: スクイントテスト（BCG方式）

スライドを **目を細めて** 見る（または縮小表示で見る）:
- **視覚的階層** が明確か（タイトルが最も目立つか）
- **情報の重み** が適切か（重要な情報が視覚的に強調されているか）
- **ホワイトスペース** が適切か（詰まりすぎ/空きすぎ）

### 改善優先度

```markdown
## 改善優先度

### Priority 1（即座に対応すべき）
- フォントサイズ基準違反の修正
- コントラスト比の改善
- テキスト折り返し問題の修正

### Priority 2（品質向上）
- アクションタイトル化
- カード高さの最適化
- ビジュアル要素の追加

### Priority 3（次回改善）
- セクション構成の見直し
- 図解・チャートの導入
- テンプレートバリエーションの拡充
```
