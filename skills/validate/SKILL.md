# 座標のオフライン検査

生成してから崩れに気づくのが一番高い。API を叩かずに座標だけで分かる不具合を先に潰す。

```bash
python <plugin>/scripts/validate_layout.py path/to/mydeck.py
python <plugin>/scripts/validate_layout.py mydeck.py --template templates/my-brand.json
python <plugin>/scripts/validate_layout.py mydeck.py --quiet    # 問題が無ければ無言
```

終了コードは問題があれば 1。CI に載せられる。

## 検出できること

| 検査 | 落ちる理由 | 直し方 |
|---|---|---|
| 図が下にはみ出す | マスターのロゴ・著作権表示・要点行と重なる | 各ブロックの高さと間隔を詰める。`DY1` が図の下限 |
| 図が左右にはみ出す | スライド外に出て見えなくなる | `X0`〜`XE` に収める |
| タイトルが 2 行になる | タイトルが `DY0` を越えて図と重なる | 全角換算 30.5 文字以内に短くする |
| 描画で例外 | 座標計算のミス、パーツの引数間違い | トレースバックの通り直す |
| レイアウトが解決できない | ロール名の綴り間違い、テンプレート未対応 | テンプレートの `roles` / `layouts` を確認 |
| プレースホルダが無い | そのレイアウトに TITLE/SUBTITLE/BODY が無い | 別のロールを使う、または `drawText` を持つレイアウトにする |
| コネクタが図形に接していない | 端点がどの図形からも 0.22in 以上離れている | `d.connect(a, b)` / `d.link(a, b)` で図形を指定する |
| コネクタが図形に埋まっている | 端点が図形の内部に 0.06in 以上入っている | 同上。意図的な線なら `free=True` |
| 文字が後から描いた図形に隠れている | バナーやゾーンが直前のブロックに重なった | 各パターンの戻り値（下端 y）を使って積む |
| 文字どうしがぶつかっている | 塗りの無いラベルが実際の文字の範囲で重なった | 位置を分ける、文言を短くする |
| 枠に対して文字が多すぎる | 必要な行数が枠の高さを超えている | 枠を高くする、文字を減らす |

## 検出できないこと（サムネイル目視が必要）

座標だけでは分からないので、`qa` スキルで必ず画像を見る。

- 文字の不自然な折り返し（枠内には収まるが「へ」だけが次行に落ちる等）
- コネクタが「正しい図形」に繋がっているか（接続の有無は分かるが、意味は分からない）
- 矢印が他の図形の上を横切っていないか（経路の良し悪しは判定できない）
- 矢印の向きや経路が意味と合っているか
- 色のコントラストが十分か
- 図が伝えたいことを実際に伝えているか

## 検査の前提

安全域は `deckkit` の定数で決まる。既定は 16:9（10 × 5.625in）テンプレートの実測値。

- `DY0 = 0.84` … 図を描いてよい上端（1 行タイトルの下）
- `DY1 = 4.30` … 図を描いてよい下端
- `NY = 4.38` / `EY = 4.86` … 要点行・補足行（`foot()` が使う。検査対象外）
- `TITLE_EM_MAX = 30.5` … タイトルが 1 行に収まる全角換算幅

ページサイズが違うテンプレートを使う場合は、デッキ側で上書きする。

```python
configure_layout(page_w=13.333, page_h=7.5, margin=0.6,
                 diagram_top=1.0, diagram_bottom=5.9,
                 note_y=6.0, edition_y=6.5)
```

`foot()` が描く要素は意図的に `DY1` より下にあるため、検査から除外される
（`FOOT_MODE` フラグで制御）。独自の下部固定要素を作る場合も同じ仕組みに乗せる。

詳細は `references/layout-contract.md` を読む。
