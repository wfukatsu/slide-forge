# 経済的価値の推定（EVE）と価値ベース・セグメンテーション
このドキュメントは、製品が顧客にもたらす経済的価値を金額で推定する方法（EVE: Economic Value Estimation）と、価値の違いで市場を切る価値ベース・セグメンテーションを扱う。価値カスケード（価値の創造 → 価値の伝達 → 価格構造 → 価格ポリシー → 価格水準 → 価格競争）の最上流「価値の創造」にあたり、下流の段はここで出した価値を前提にする。価格の上限を金額で出すとき、次善の競合代替品を決めるとき、価格のためのセグメントを切るとき、scripts/pricing/eve_calc.py（セグメントごとの総経済価値と差別化価値の比率を計算する）の入力を作るときに読む。

## 要点
- 価格の拠り所は使用価値（use value、製品から得る総効用）ではなく、代替品によって決まる経済的価値（economic value、交換価値）である。
- 総経済価値（total economic value）は、参照価値（reference value）に正の差別化価値（differentiation value）を足し、負の差別化価値を引いたものである。これは「十分な情報を持つ買い手が払う最大額」であり、上限であって請求価格ではない（[1] p.29）。
- 参照価値の起点は、次善の競合代替品（next-best competitive alternative, NBCA）の価格である。
- 価値には金銭的価値（monetary value、コスト削減や収益増加）と心理的価値（psychological value、安心や威信）がある。前者はデプスインタビューと価値ドライバー（value driver、顧客の経済性や満足を左右する要因）ごとの算式（価値ドライバー・アルゴリズム）で、後者はコンジョイント分析で推定する。
- 知覚価値（perceived value、買い手が実際に認識している価値）は、情報が足りないために経済的価値を下回るのが普通である。売れない理由が「価値に比べて高い」のか「価値が知られていない」のかを見分けられることが、EVEの最大の効用である（[1] p.40）。
- 「性能がx%良いならx%高くできる」という考えや、品質と価格の平均的な関係（公正価値線）で価格を決めるのは誤りである。参照価値は競争によって使用価値より低く抑えられるが、差別化価値は1対1で価格プレミアムになりうる（[1] p.45–47）。
- 価格のためのセグメントは、人口統計ではなく「顧客にとっての価値」と「売り手のコスト・制約」が重なるところで切る（手順8）。

## 判断基準・使い分け
| 区分 | 定義 | 推定手段 | 注意 |
|---|---|---|---|
| 参照価値 | 次善の競合代替品の価格。単位と条件を揃えたもの | 公開価格、営業への聞き取り、顧客が提示する競合価格 | 数量やサービス水準で正規化しないと比較できない |
| 正の差別化価値 | 代替品より優れる点の顧客経済上の価値 | 価値ドライバー・アルゴリズム | コスト削減か追加便益のどちらか一方で測り、二重計上しない |
| 負の差別化価値 | 劣る点、乗り換えコスト、新規ベンダーのリスク | 同じ | 省かない。値引きの最小幅の根拠になる |
| 金銭的価値 | コスト回避、収益増、リスク低減、時間短縮 | デプスインタビュー（顧客の業務を掘り下げる面談） | B2Bの主役 |
| 心理的価値 | 安心、地位、快適さ、利便性 | コンジョイント分析（conjoint analysis、選択課題から属性ごとの支払意思額（払ってもよい最大額）を推定する調査）、他所で同じ安心に払っている額 | 削らない。ただし革新的で想像しにくい便益にはコンジョイントが効きにくい |

### 次善の競合代替品を決めるときの落とし穴
| 落とし穴 | 内容 | 対処 |
|---|---|---|
| 市場の近視眼 | 競合を同業に限ってしまう | 「自社がなければ顧客は何をするか」を顧客の言葉で問う |
| バスケット型の代替 | 複数製品の組み合わせが代替になっている | 組み合わせの合計価格を参照価値にする |
| 何もしないこと | 必要性に気づかないことが最大の競合になっている | 参照価値を0とし、すべてを差別化価値として伝える |

### 差別化価値の比率の読み方
差別化価値の比率 = (Σ正の差別化価値 − Σ負の差別化価値) / 総経済価値。比率が高い（目安は50%超）なら価値で売ってプレミアムを守れる製品である。比率が低いなら価格で比べられる製品であり、価格水準よりも構造と伝達が重要になる。

## 手順
1. **セグメントと単位を決める。** 価値は用途で変わるので、セグメントごとに推定する。1ユーザー年、1取引、1拠点などの使用単位と期間に揃える。
2. **次善の競合代替品を特定する。** 自社がなければ顧客は何をするか（競合X、内製や手作業、何もしない）。その総コストを同じ単位に換算したものが参照価値になる。代替品がセグメントで違えば、参照価値もセグメントごとに持つ。
3. **価値ドライバーを列挙する。** 顧客の経済性を変える要因（コスト回避、収益増、リスク低減、時間短縮）と負の要因（乗り換えコスト、欠けている機能、教育、新規ベンダーのリスク）を挙げ、金銭的か心理的かを分ける。デプスインタビューで顧客のビジネスモデルを掘り下げて集める。
4. **各ドライバーをアルゴリズムにする。** 入力は顧客が自分で知っている数字にする。
   ```
   時間削減の価値   = 月あたり削減時間 × 負担込み時給 × 12
   障害削減の価値   = 年間障害件数 × 1件あたりコスト × 削減率
   新規受注の価値   = 対象案件の割合 × 受注できる割合 × 1件あたり貢献利益
   ```
   今はセグメントの典型値を入れ、後で営業が顧客自身の値に置き換える。典型値の出所を明記する。精密に間違うより、おおよそ正しい方がよい。定量化が難しいからといって重要なドライバーを落とさない。
5. **合計する。**
   ```
   総経済価値 = 参照価値 + Σ正の差別化価値 − Σ負の差別化価値
   差別化価値の比率 = (Σ正 − Σ負) / 総経済価値
   ```
   合計の原則は3つある（[1] p.36）。代替品との差分だけを評価する（共通の便益はすでに参照価値に入っている）。コスト削減か追加便益かの一方で測る。価値が性能に比例するとは仮定しない（寿命が2倍になってライン停止が半分になれば、価値は2倍を大きく超える）。
6. **価値プロファイルを作る。** ドライバーを金額の大きい順に並べたものを価値プロファイルと呼ぶ。上位2〜3個が販売メッセージになり、検証を最も厚くする対象になる。セグメント別の価値と市場規模を並べると、どこをいくらで攻めるかが見える。
7. **診断する。** 価格が経済的価値より低いのに売れないなら伝達の問題であり、価格を下げずに市場を教育する（伝え方は [value-communication.md](value-communication.ja.md)）。経済的価値そのものが価格を下回るなら、値下げか価値の再設計が必要になる。
8. **価値ベース・セグメンテーション（6ステップ）を行う**（[1] p.49–54）。
   1. 既存の調査や統計から市場の一次マップを作る。
   2. 識別力のある価値ドライバーを特定する。セグメント間で差が大きく、セグメント内では揃っているドライバーを探す。
   3. 自社の運用上の制約と優位を把握する。活動基準原価計算（活動ごとのコストを顧客に割り当てる方法）で顧客ごとのサービスコストを出し、競合と比べる。
   4. 一次セグメントと二次セグメントを作る。一次は顧客ニーズと自社制約の戦略的重なり（strategic overlap）で、二次はその中で最も差の大きいドライバーで切る。
   5. 営業が顧客を見て判別できる業務用語でセグメントを記述する。
   6. 価格メトリクス（課金の単位）と価格フェンス（セグメント別の価格を適用する条件）を設計する。詳細は [price-structure.md](price-structure.ja.md)。

### scripts/pricing/eve_calc.py の入力スキーマ

```json
{
  "unit": "per site per year",
  "currency": "USD",
  "segments": [
    {
      "name": "Mid-size manufacturers",
      "reference": {"alternative": "Vendor X + in-house integration", "value": 30000},
      "drivers": [
        {"name": "Integration labor avoided", "short": "Labor avoided", "type": "monetary", "sign": "+",
         "formula": "hours × rate", "inputs": {"hours": 400, "rate": 90},
         "units": {"hours": "h", "rate": "USD/h"}},
        {"name": "Downtime avoided", "type": "monetary", "sign": "+",
         "formula": "incidents × cost × reduction", "inputs": {"incidents": 6, "cost": 12000, "reduction": 0.5}},
        {"name": "Vendor risk (new supplier)", "type": "psychological", "sign": "-", "value": 5000}
      ],
      "price": 24000
    }
  ]
}
```

各ドライバーには `value` を直接与えるか、`formula` と `inputs` を与える。式では `×`、`*`、`+`、`-`、`/`、`÷`、括弧、入力名が使える。スクリプトはセグメントごとの合計、差別化価値の比率、価値プロファイルを出力する。

スライドを作るとき（`--slides DIR`、`--slides-logic`）だけ使う任意の項目:

| 項目 | 意味 |
|---|---|
| `short` | 図の棒ラベルに使う短い名前。6〜7 本の棒が並ぶので 6 字程度に収める |
| `units` | 入力ごとの単位。計算ロジックのスライドで数値の後に付く（例: `{"docs": "件", "rate": "円/時"}`）。括弧で始まる単位は数値の直後に付く（例: `"prob": "（年間発生確率）"`）。書かない入力は数値だけになり、読み手が検算できない |
| `price` | セグメントの推奨価格（または現行価格）。「顧客に残す価値」（総経済価値 − 価格）の算出に使う |

## チェックリスト
- [ ] セグメントごとに推定し、単位と期間を揃えている
- [ ] 次善の競合代替品を顧客の視点で特定し、何もしないことや内製も検討している
- [ ] 参照価値を数量やサービス水準で正規化している
- [ ] 負の差別化価値（乗り換えコスト、リスク、欠けている機能）を計上している
- [ ] 各ドライバーに式、入力値、その出所がある
- [ ] コスト削減と追加便益を二重計上していない
- [ ] 心理的価値を削除せず、推定方法を示している
- [ ] 総経済価値を上限として扱い、請求価格と混同していない
- [ ] 上位のドライバーが販売メッセージと検証計画につながっている
- [ ] セグメントがコストと制約の側面も含み、営業が判別できる言葉で書かれている

## よくある失敗と対処
| 失敗 | 対処 |
|---|---|
| 顧客が口にした支払意思額を平均する | 買い手は交渉のために価値を低く言い、経験していない便益は評価できない。アルゴリズムで推定する |
| 属性ごとの品質スコアに価格を回帰させた「公正価値線」で決める | 差別化の大きい製品の価値を過小評価し、平均的な製品の価格になってしまう。差別化価値は別に積み上げる |
| 売り手のコスト削減を顧客価値とみなす | 価値は顧客の経済性で測る |
| 「性能2倍なら価格2倍まで」と考える | 参照製品を多く買えば同じ便益が得られる場合に限った話である。顧客の価値ドライバーで計算し直す |
| 人口統計や企業規模だけでセグメントを切る | 支払動機とサービスコストが違う軸で切り直す |
| 差別化が正味でマイナスなのに大幅に値引きする | EVEで乗り換えを検討させる最小の値引き幅を出し、非価格の手段（例: 現地在庫で納期を縮める）で劣位を消す |
