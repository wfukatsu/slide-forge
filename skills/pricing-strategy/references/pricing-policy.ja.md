# 価格ポリシー

値引き・例外・値上げ・販促・価格への異議など、「個々の取引で価格をどう動かすか」の規則を扱う。価値カスケード（価値の創造 → 価値の伝達 → 価格構造 → 価格ポリシー → 価格水準 → 価格競争）の 4 段目で、価格表を取引の現場で崩さないための段階である。値引きの規則を書くとき、既存の値引き慣行を診断するときに使う。

## 要点

- 価格ポリシー（pricing policy）は、特定の顧客・期間・取引で価格を変える基準を定め一貫して適用する規則である。目的は顧客の期待と購買行動を売り手に有利な方向へ導くこと。
- 顧客が「粘れば安くなる」と学ぶと定価は通らなくなる。その期待を作るのは売り手自身の場当たり的な値引きである。
- 値引きの承認階層は価格ポリシーではなく人事ポリシーである。顧客は「上に上げれば安くなる」と学ぶだけだ。
- 例外の要求は「同じ条件の顧客全員に適用するルールを作る機会」として扱う。問いは「同じ条件の全顧客にこの価格を出しても利益が出るか」。
- 譲歩は必ずギブ・ゲット（give–get: 譲る代わりに何かを得る交換）にする。数量、契約期間、サービス削減、前払い、事例公開などを得ずに価格を下げない。
- 譲歩は時期・増分量・一時金・期限付きクレジットで与え、基準価格は崩さない。譲歩価格は次の交渉の出発点になる。
- 請求書価格ではなくポケット価格（pocket price: 請求書外の譲歩まで引いた手取り価格）で管理する。定価からの目減りを段ごとに並べる価格ウォーターフォール（price waterfall）上で、見えにくい譲歩ほど膨らむ。

## 判断基準・使い分け

### 場当たり的な価格とポリシーに基づく価格

| 観点 | 場当たり的（受動的） | ポリシーに基づく（能動的） |
|---|---|---|
| 値引きの根拠 | 顧客の抵抗、承認者の裁量 | 事前に定めた条件 |
| 顧客が学ぶこと | 抵抗・脅し・直訴は報われる | 価格は価値とのトレードオフでしか動かない |
| 帰結 | 価格の整合性（price integrity: 提示価格を他の顧客も払っているという信頼）が崩れる悪循環 | 顧客が情報を開示し、新しい選択肢が生まれる好循環 |

### 買い手タイプ別の異議対応

軸は差別化の重要度と探索コスト（比較の難しさ）（[1] Exhibit 5-4）。

| タイプ | 位置 | ポリシー |
|---|---|---|
| 価値重視 | 差別化重要・探索容易 | 価値の源泉をアンバンドルし、ギブ・ゲットで交換する。「引き下がる」「無償で譲歩する」以外の選択肢を営業に持たせる |
| ブランド重視 | 差別化重要・探索困難 | 値引きしない。失望には補償（初年度クレジットなど）で、払いすぎ感には差別化サービスの可視化で応える |
| 価格重視 | 差別化不要・探索容易 | 仕様ぎりぎりまでコストを削った版で応じる。既存顧客には魅力がなく、理由を説明できる形にする。割に合わなければ撤退する |
| 利便性重視 | 差別化不要・探索困難 | 異議はまれ。手軽さを提供し、その対価を取る |

価値重視の買い手が価格重視を装うサインは、「仕様が曖昧」「最安値で決めると約束しない」ことである。対策は「仕様が確定するまで入札しない」と公言することだ。

### プロの買い手の戦術と処方箋

| 戦術 | 処方箋 |
|---|---|
| 提案のコモディティ化（封印入札・逆オークション） | 仕様を満たすが超えない版で応じ、急ぎ納期などは有償。見せかけの入札には不参加か定価 |
| 値上げ率の割引要求（25% 割引の大口が 6% 値上げを 4.5% に） | 割引後ベースなので値上げ額はすでに小さい（$6 でなく $4.50）。率の例外は作らず時期で譲る |
| 数量割引（10% 増やすから全量を 2% 引け） | 増分への実効割引率（22%）を示し、割引は増分だけに年末リベートで払う |
| 過去の失敗の穴埋め | 一時金か上限付きクレジットで補償し、価格は崩さない |

パワーバイヤー（power buyer: 購買量を背景に最安値を求める買い手）には、競わせる（独占的に売れるものを与える）、自社の価値を定量化する、不要コストを削った専用供給、製品ラインを分ける、分断統治に抵抗する（全製品採用を条件に最安値）の 5 策で臨む。

## 手順

### A. 値引き・交渉ポリシーを書く（最初の取引の前に）

1. **現状を測る**。同じ製品・数量・条件なのに著しく安く買っている「アウトロー（outlaw）」顧客を特定する。同条件の取引価格のばらつきを見るプライスバンド分析（[pricing-capability.md](pricing-capability.ja.md)）を使う。
2. **ポケット価格を算出する**。
   ```
   ポケット価格 = 定価 − 請求書上の値引き − 請求書外の譲歩
   請求書外の譲歩 = 数量リベート + 支払条件割引 + 協賛金 + 送料免除 + 無償サービス + 販促費 …
   ```
   顧客別のばらつきが、価値やサービスコストの差で説明できるか確認する。
3. **ギブ・ゲット表を作る**。営業が承認なしに出せる事前承認済みトレードオフと上限を列挙する（例: 複数年契約→年末リベート、増分数量→増分への割引、納期緩和→下位構成、前払い→支払条件割引、事例公開→導入支援の追加）。
4. **値引き禁止リストを作る**。定価が虚構だと示す値引き（中核階層の定価など）やセグメント間で漏れる値引き。
5. **例外の記録規則を決める**。理由付きで記録し、繰り返す例外は構造かポリシーを直す。
6. **数量割引の実効割引率を検算する**。
   ```
   増分に対する実効割引率 = 割引率 × (既存量 + 増分量) / 増分量
   例: 2% × 110 / 10 = 22%
   ```

### B. 価格への異議に応える

1. 何と比べているかを聞き、参照価値（比較の基準）が誤っていれば正す（[value-communication.md](value-communication.ja.md)）。
2. 買い手タイプを判定する。
3. 価値の根拠を買い手自身の数字で示し直す（[economic-value.md](economic-value.ja.md)）。
4. 下げるならギブ・ゲット表か、価値を減らした下位構成で。同じオファーは安くしない。
5. 価格だけを求め続けるなら、価格の床（[price-level.md](price-level.ja.md)）でも取る価値があるか判断し、その取引を他顧客の参照価格にしない。

### C. 値上げを管理する

1. 業界全体のコスト事情と因果関係、値上げ幅、実施日を公表する。数か月前に通知する。
2. 「業界の顧客全員に撤回しない限り、誰にも撤回しない」。主要顧客には、その競合が有利な条件を得たら遡って同条件にする移行保証（transition guarantee）を与える。
3. 譲歩は実施時期に限る。抵抗した顧客だけ免除すると「抵抗は報われる」と教える。
4. 柔軟価格（営業に値引き裁量を与える方式）から移行するときは、アウトローから着手する。上位役職者が「他顧客に不公平だ」と伝え、営業がギブ・ゲットで口座を救う。長期契約に応じれば値上げを 3 回に分ける。応じない価格重視の買い手からは撤退する。

### D. 販促・不況期

1. 販促はトライアル誘導に限り、見込み客だけに届く手段を使う。常連が学習するパルス型販促は将来の支払意思額を下げ、需要を前借りするだけである。
2. 値引きより返金保証・成果保証を優先して価格を保つ。
3. サービスの初年度割引は更新時に損失と感じられ、解約を招く。価格は据え置き、無料ギフトやクレジットで誘導する。
4. 不況期は近接競合からシェアを奪う値下げをしない。長期契約と引き換えに顧客市場の指標へ価格を連動させ、数量は厳格にフェンスした新セグメントから取る。

## チェックリスト

- [ ] 値引きの根拠が事前の条件で説明され、承認階層だけに頼っていない
- [ ] ギブ・ゲット表（上限付き）と値引き禁止リストがある
- [ ] 例外の記録と、繰り返す例外を価格構造に反映する規則がある
- [ ] 顧客別ポケット価格を請求書外の譲歩込みで算出した
- [ ] 数量割引は増分だけに効き、実効割引率を検算した
- [ ] 異議対応が買い手タイプ別に分かれている
- [ ] 値上げ計画に根拠、通知時期、撤回の規則、時期による譲歩がある
- [ ] 価格の情報交換などの法的論点を [ethics-legal.md](ethics-legal.ja.md) で確認した

## よくある失敗と対処

| 失敗 | 対処 |
|---|---|
| 承認階層を価格ポリシーと呼ぶ | 条件ベースのギブ・ゲット表に置き換える |
| 失注が怖くて無条件に値引きする | ギブ・ゲットを示して異議の正体を見極める。必要なら全対象顧客に能動的に値下げする |
| 大口に値上げ率の割引を認める | 割引の二重取りだと示し、実施時期で譲る |
| 請求書価格だけで収益性を見る | ウォーターフォールでポケット価格を出し、送料免除など監視の緩い譲歩から締める |
| 移行計画なしに「一切値引きしない」と宣言する | アウトローから段階的に是正する |
