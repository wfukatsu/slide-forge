# 戦略的プライシング能力の構築

価格戦略を組織が実行できるようにするための、人材、組織構造、データと分析ツールの整え方を扱う。価値カスケード（価値の創造 → 価値の伝達 → 価格構造 → 価格ポリシー → 価格水準 → 価格競争）の各段で決めた戦略を、現場で一貫して実行させる土台にあたる。戦略が現場で実行されない、割引が統制できない、価格組織や営業報酬を設計し直す、能力を診断する、といった場面で使う。

## 要点
- 能力は3本の柱のバランスで決まる。人材、組織構造（決定権・プロセス・インセンティブ）、データと分析ツールである。どれか1本だけに投資しても成果は出ない。
- 価値に基づく戦略と強い実行力をあわせ持つ企業（Value Masters）の営業利益は、業界平均の1.24倍である。実行力だけが高い企業（Runaway Trains）は0.91倍で最下位になる（[1] p.263）。実行力があっても方向が間違っていれば、損失が早く大きくなるだけである。
- 良い戦略が失敗する最大の理由は、プロセスとインセンティブが戦略目標と矛盾していることである。
- 集権化の程度は事業の多様性で決める。選択肢は集権型、専門知識センター、専任サポート部門の3つである。
- 決定権は4種類に分けて明示する。Input（情報提供）、Make（決定）、Ratify（承認・覆す）、Notify（通知を受ける）である。Make と Ratify は別の人に持たせる。
- 売上高に比例する営業報酬は、利益を削る値引きを促す。収益性係数（キッカー）で調整した販売クレジットに切り替えれば、コストを開示せずに報酬を利益に結びつけられる。
- 利益漏れは2種類の分析で見つける。顧客分析（勝敗分析、顧客収益性）とプロセス分析（プライスバンド、価格ウォーターフォール）である。
- システムの要件は戦略が決める。逆にシステムに戦略を決めさせてはならない。変革を進めるには、経営幹部が言行を一致させることと、対照群を置いたデモンストレーション・プロジェクトが要る。

## 判断基準・使い分け

### 組織の原型
| 原型 | 決定の所在 | 本社の役割 | 適する状況 |
|---|---|---|---|
| 集権型（Centralized Pricing） | 本社 | 決定と管理。事業部はデータ収集と遵守を担う | 単一市場。コモディティ的な業界。1つの価格変更が他の市場に波及する業界（航空など） |
| 専門知識センター（Center of Expertise） | 事業部 | 高度な分析、ベストプラクティスの共有、社内コンサル | 現地の条件が強い市場（小売、通信など） |
| 専任サポート部門（Dedicated Support Unit） | 各事業部の専任組織 | 緩い連携にとどまる | 市場の重複が少ない多角化企業 |

### 決定権の割り当て例
| 権利 | 典型的な保持者 | 注意点 |
|---|---|---|
| Input | 財務、需要予測、営業現場、市場調査 | 商業的な成果への責任は負わない |
| Make | 価格責任者、または1つの委員会 | 保持者は1人か1委員会に限る |
| Ratify | 上級管理者 | 全社の優先事項と矛盾する決定だけを覆す |
| Notify | 製品開発、オペレーション、請求 | 決定を自分の判断に使う人に通知する |

### 分析ツールの使い分け
| 分析 | 答える問い | 次の打ち手 |
|---|---|---|
| 勝敗分析 | 競合に勝つか負けるか。その理由は何か | 価格か差別化のどちらかを修正する。ただし目標は勝率ではなく利益貢献である |
| 顧客収益性マップ | 誰が儲かり、誰が儲からないか（顧客ごとの価格とサービス提供コストで見る） | 高マージンの小口顧客はプレミアムを払う理由を理解して守る。大口で低収益の顧客は値上げかコスト削減の対象にする |
| プライスバンド | 同じ条件の取引で、ピア価格（数量・サービス・地域などの正当な要因で回帰して求めた価格）から外れているのは誰か | 外れ値の原因を仮説化して検証し、方針で是正する |
| 価格ウォーターフォール | 定価から割引・リベート・支払猶予・無償サービスなどを順に差し引いたとき、ポケット価格（すべて差し引いた後に実際に残る価格）はいくらか | 漏れの大きい段階の運用ルールを締める（送料免除に書類を求める、など） |

### システムの機能
商用システムの機能は4つある。価格分析、価格最適化（競合価格が全て見える市場で有効）、価格管理（ERP 連携による価格表の一括更新）、ディール管理（方針の範囲内での見積もりと承認記録）である。表計算や BI ツールで分析を標準化してから、専用ソフトを検討する。

## 手順
1. 上位5人の経営幹部に、自社の価格戦略を各自で説明してもらう。答えが食い違えば、戦略が共有されていない。
2. 価値カスケードの6要素（価値の創造、価値の伝達、価格構造、価格ポリシー、価格水準、価格競争）それぞれを3次元で評価する。3次元とは、戦略の明確さ、組織の整合と責任者、システムの有無である。成熟度は Basic、Reactive、Progressive、Optimized、Preeminent の5段階で付ける（[1] Exhibit 11-4）。各要素の中身は [value-cascade.md](value-cascade.ja.md) にある。
3. 事業の多様性から組織の原型を選ぶ。そのうえで、主要な価格決定ごとに Input、Make、Ratify、Notify を一覧表で割り当てる。
4. 価格プロセスを4段階で整える。最初に主要活動を定義する（機会評価、価格設定、交渉、特急注文への課金、契約、請求を含める）。次に現行の流れを図に描く。続いて利益漏れの箇所を特定する。最後に決定権を含めて再設計する。
5. 決定権を持つ全員について、現行の評価指標を文書化して対立を可視化する。営業には販売クレジットを導入する。計算式は「販売クレジット = [目標価格 − k ×（目標価格 − 実際価格）] × 数量」で、k は目標価格における貢献利益率（貢献利益 ÷ 価格。貢献利益は価格 − 単位あたり増分コスト）の逆数以上にする。例: 貢献利益率 20% なら k = 5 で、15% の値引きはクレジットを 75% 減らす（[1] p.278）。
6. 12〜36か月分の取引データを集める。範囲は定価、請求価格、割引、リベート、返品、送料、サービス消費、顧客別損益である。そのうえで、価格ウォーターフォール、プライスバンド、顧客収益性の分析を実行する。
7. 対象と期間を絞り、評価指標を1つに決めたデモンストレーション・プロジェクトを設計する。類似した2つの顧客群を用意し、一方にだけ新しい方針を適用する。早い段階で成功を示し、全社に展開する。
8. 経営幹部の役割を決める。研修の義務化、定期レビュー、支持の表明、自ら例外を作らないことである。

## チェックリスト（能力診断）
- [ ] 上位の経営幹部が、価格戦略を同じ言葉で説明できる
- [ ] 価値カスケードの6要素それぞれに成熟度評価と責任者がある
- [ ] 組織の原型（集権型、専門知識センター、専任サポート部門）が事業構造に合っている
- [ ] 主要な価格決定ごとに Input、Make、Ratify、Notify が文書化され、Make と Ratify が分離している
- [ ] 価格プロセスが、割引承認だけでなく交渉、特急課金、契約、請求まで含んでいる
- [ ] 割引に、事前に定義された適用条件（ギブ・ゲット（give-get）: 割引と引き換えに顧客から得る見返り）がある。場当たりの承認が既定になっていない（[pricing-policy.md](pricing-policy.ja.md) を参照）
- [ ] 営業報酬が売上高ではなく、収益性で調整された指標に連動している
- [ ] 部門ごとの評価指標（売上高、シェア、粗利益率、稼働率）の矛盾が把握されている
- [ ] 取引単位の価格データ（ポケット価格まで）を12か月以上分析できる
- [ ] 勝敗、顧客収益性、プライスバンド、価格ウォーターフォールを定期的にレビューしている
- [ ] システム投資の要件が、価格戦略から導かれている
- [ ] 新しい施策を、対照群のある実験で検証してから展開している

## よくある失敗と対処
- **ツールへの先行投資。** 航空業界はイールド管理ツールを使った価格戦争で、それまでの累積利益を失った（[1] p.265）。戦略と組織を先に整えてから、ツールの要件を決める。
- **経営幹部が「今回限り」の例外を認める。** 例外が常態化し、戦略が放棄される。例外は Ratify の手続きでしか認めない。
- **財務が一律の粗利益率の基準で拒否する。** 営業は迂回策に時間を使い始める。価値とセグメントを考慮した基準に変え、支払条件などの方針で制約する。
- **勝率を目標にする。** 価格を下げれば勝率は上がる。数量の増加がマージンの減少を補ったかどうかを確認する。
- **請求書価格だけを見る。** 漏れの大半は請求書の後で起きる（支払猶予、無償サービス、リベート）。価格ウォーターフォールで、ポケット価格まで追う。
- **デモの範囲を広げすぎる。** 関心が薄れ、結果の因果関係も曖昧になる。期間、対象、指標を絞り、対照群を置く。
