# 価格決定の財務分析

価格変更の是非を、増分コストと損益分岐販売変化率で数字にする方法を扱う。価値カスケード（価値の創造 → 価値の伝達 → 価格構造 → 価格ポリシー → 価格水準 → 価格競争）では、価格水準と価格競争の判断を支える計算にあたる。価格変更、新ティア、競合への追随の評価と、`scripts/pricing/breakeven.py`（候補価格ごとの損益分岐販売変化率と利益影響を計算する）の入力作成に使う。

## 要点

- 問うのは「この価格で黒字か」ではなく「代替価格に勝つには販売量がどれだけ変わればよいか」である。需要曲線を知らなくても、必要な変化が現実的かを判断すればよい。
- 使うコストは増分コスト（incremental cost、その決定で追加で発生するコスト）かつ回避可能コスト（avoidable cost、決定しだいで避けられるコスト）だけである。配賦した間接費、埋没費用（sunk cost）、どのみち存在する設備は除く。
- 固定費でも価格変更の実施に伴うもの（キャンペーン、新しい支援体制、増設）は増分固定費として入れる。半固定費は販売量の範囲次第で増分になる。
- 基本式は「損益分岐販売変化率（breakeven sales change、価格変更後も総貢献利益を保つのに必要な販売量の変化率）= −ΔP / (CM + ΔP)」である。ΔP は価格変化、CM は貢献利益（contribution margin、価格 − 単位あたり増分コスト）である。変動費の変化、増分固定費、反応的価格変更、金額ベースへ拡張できる。
- 値下げと値上げは非対称である。貢献利益率（CM ÷ 価格）45% なら 10% 値下げに約 29% の販売増が要るが、10% 値上げは約 18% の販売減まで耐える。
- 比較の基準はベースライン（価格を変えなかった場合の販売）であり、今日の販売量ではない。
- 低価格の新ティアは共食い（cannibalization、高価格品の販売が低価格品に置き換わること）を起こす。純置換比率と総置換比率を区別して示す。
- 非増分の固定費と埋没費用を価格に上乗せしない。コストを考えるべき時点は、まだ回避できる投資の前である。

## 判断基準・使い分け

### 関連コストの判定

| コスト | 扱い | 理由 |
|---|---|---|
| 変動費（原材料、決済手数料、従量のインフラ費） | 入れる | 販売量とともに変わる |
| 価格変更に直接伴う固定費（新価格の告知、割引の広告、専用の支援体制） | 増分固定費として入れる | その決定がなければ発生しない |
| 半固定費（一定量を超えると増設が要る設備・人員） | 範囲を超えるなら入れる | 販売量の範囲で増分かが変わる |
| 過去の開発費、リース期間中の賃料 | 除く | 埋没費用で、今の決定で変わらない |
| 配賦された本社間接費、R&D | 除く | 価格案で総額が変わらない |
| 在庫品の原価 | 取替原価で入れる | 販売のコストは次に補充する費用である（NIFO: next-in, first-out） |
| 転売できる資産の保有コスト | 残存価値の分は回避可能 | 資産を手放せば避けられる |
| 失う高価格販売の貢献（機会費用） | 入れる | 共食い・能力の奪い合いを見落とさない |

## 手順

1. ベースラインを定める。価格を変えなかった場合の販売量・貢献利益を置く。成長市場なら成長後の見込み、発売なら代替価格で見込む販売量である。
2. 関連コストを特定し、単位あたり貢献利益を出す。

   ```
   CM  = 価格 − 単位あたり増分コスト
   %CM = CM ÷ 価格
   ```

3. 基本式で損益分岐販売変化率を計算する。ΔP は値下げなら負。CM と ΔP は同じ単位（金額・%・小数のいずれか）で揃える。

   ```
   損益分岐販売変化率 = −ΔP / (CM + ΔP)
   損益分岐販売変化量 = 損益分岐販売変化率 × ベースライン販売量
   利益の増減 = (実際の販売変化量 − 損益分岐販売変化量) × 新CM
   ```

   値下げはこれ以上の販売増が要る。値上げはこの範囲までの販売減なら得になる。
4. 必要に応じて拡張する。

   ```
   # 変動費も変わる場合（金額単位で計算する）
   ΔCM = ΔP − ΔC
   損益分岐販売変化率 = −ΔCM / (CM + ΔCM) = −ΔCM / 新CM

   # 増分固定費 IFC がある場合（固定費を回避できるなら IFC は負）
   損益分岐販売変化率 = −ΔP / (CM + ΔP) + IFC / (新CM × ベースライン販売量)
   損益分岐販売変化量 = ベースライン販売量 × (−ΔP / (CM + ΔP)) + IFC / 新CM

   # 反応的価格変更（競合への追随）
   反応的損益分岐販売変化率 = 価格変化率 / 貢献利益率      # = ΔP / CM
   値下げへの追随が得なのは: 追随しない場合の販売損失率 > −ΔP / CM
   競合の値上げに追随しないのが得なのは: 追随しない場合の販売増加率 > ΔP / CM
   （値下げへの追随は scripts/pricing/breakeven.py --reactive で算出。単位コストも変わる場合は (CM前 − CM後) / CM前）

   # 金額（売上高）ベースへの換算
   %BE(金額) = %BE(数量) + %ΔP × (1 + %BE(数量))
   ```

5. 販売変化のシナリオ表を作り、増分固定費を差し引いた利益の変化を並べる（what-if 表）。`scripts/pricing/breakeven.py` の `volume_scenarios_pct` で出せる。
6. 複数の価格案を比べるときは損益分岐販売曲線（breakeven sales curve）を描く（[1] Exhibit 9-5 / 9-6）。縦軸が価格、横軸がその価格で同じ利益を得るのに必要な販売量である。実際の販売量が曲線の右なら利益が増え、左なら減る。
7. 価格弾力性（price elasticity、販売数量の変化率 ÷ 価格の変化率）は逆から問う。「自社の弾力性はいくらか」ではなく「この決定を正当化するのに必要な最小（値上げなら許容できる最大）の弾力性はいくらか」を出し、市場がそれより弾力的か非弾力的かを判断する。判断材料は [measurement.md](measurement.ja.md)（価格感応度の測定手法）で集める。
8. 販売反応を判断する。値下げ案には必要な販売増を達成する根拠と計画を、値上げ案には販売を維持できる根拠と顧客への説明を求める。競合の反応は [price-competition.md](price-competition.ja.md)（価格競争への対応）で確認する。
9. 実施後、実際の販売変化が損益分岐を超えているかを追跡する。

### 数値例（価格 10.00、単位増分コスト 5.50、CM 4.50 = 45%、ベースライン 4,000 個）

| 価格変化 | 新価格 | ΔP | 損益分岐販売変化率 | 必要な販売量 |
|---|---|---|---|---|
| +25% | 12.50 | +2.50 | −2.50 / 7.00 = −35.7% | 2,571 |
| +15% | 11.50 | +1.50 | −1.50 / 6.00 = −25.0% | 3,000 |
| +10% | 11.00 | +1.00 | −1.00 / 5.50 = −18.2% | 3,273 |
| +5% | 10.50 | +0.50 | −0.50 / 5.00 = −10.0% | 3,600 |
| −5% | 9.50 | −0.50 | 0.50 / 4.00 = +12.5% | 4,500 |
| −10% | 9.00 | −1.00 | 1.00 / 3.50 = +28.6% | 5,143 |
| −15% | 8.50 | −1.50 | 1.50 / 3.00 = +50.0% | 6,000 |
| −20% | 8.00 | −2.00 | 2.00 / 2.50 = +80.0% | 7,200 |

- 増分固定費込み: −15% で IFC 2,400 なら 50% + 2,400 / (3.00 × 4,000) = 70%（6,800 個）。
- −5% で半固定費 800（1,000 個ごと）なら 12.5% + 800 / (4.00 × 4,000) = 17.5%（700 個増）。販売 20% 増（800 個）なら (800 − 500) × 4.00 − 800 = +400。
- 変動費を 0.22 下げつつ 5% 値下げ: ΔCM = −0.50 + 0.22 = −0.28 → 0.28 / 4.22 = +6.6%（265 個）。
- 金額ベース: 5% 値下げの 12.5% は 0.125 + (−0.05)(1.125) = +6.9% の売上高増に相当する。
- 反応的: 競合が 15% 値下げ → −15% / 45% = −33.3%。追随しないと 33.3% を超えて失うときだけ追随する。`--price 10 --cost 5.5 --candidates 8.5 --reactive` で同じ 33.3% が出る。
- 成長するベースライン（%CM 55%、据え置きでも 2,000 → 2,400 個）: 5% 値下げの 10% は 240 個であり、現在の 2,000 個で計算すると 200 個と過小評価する。
- 固定費回避（[1] 付録 9A の事例。値上げで設備 9,000 を建てずに済む。%CM 58.5%、10% 値上げ、ベースライン 45,000 個、新CM 2.635）: −14.6% + (−9,000) / (2.635 × 45,000) = −22.2%。

### 共食い（低価格ティアの追加）

Full の横に安い Lite を置くと、乗り換えた顧客は Full の貢献を払わなくなるが Lite の貢献は払う。二つの比率は答える問いが違うので、どちらを示したかを必ず書く。

| 比率 | 式 | 答える問い |
|---|---|---|
| 純置換比率 | (CM_full − CM_lite) ÷ CM_lite | 1 人の Full 顧客の乗り換えを埋めるのに、何人の新規 Lite 顧客が要るか |
| 総置換比率 | CM_full ÷ CM_lite | Lite 何個で Full 1 個分の貢献になるか |

例: Full 120k、増分コスト 45k（CM 75k）。Lite 60k（CM 15k、同コスト）なら純 4.0、総 5.0。Lite 75k（CM 30k）なら純 1.5、総 2.5。Lite 投入の判定は次のとおり。

```
新規 Lite 数量 × CM_lite  >  乗り換え数量 × (CM_full − CM_lite) + Lite の増分固定費
```

共食いは主に価格水準ではなく価格構造の問題である。Lite を価格フェンス（price fence、買い手の属性や購買条件で価格を分ける条件）で囲い（容量・ユーザー数の上限、買い手規模の条件、エンタープライズ機能なし、アップグレード時の充当）、Full の買い手だけが必要とするものを削って乗り換え率を下げる。設計は [price-structure.md](price-structure.ja.md)（価格構造と価格フェンス）を参照する。

### 基本式の導出（[1] 付録 9B）

価格 P、販売量 Q、単位変動費 C とする。値下げで既存販売 Q に対して ΔP × Q の貢献を失い（価格効果、長方形 A）、追加販売 ΔQ に対して (P + ΔP − C) × ΔQ の貢献を得る（数量効果、長方形 B）。変更前後の利益を等しいとおく。

```
(P − C)Q = (P + ΔP − C)(Q + ΔQ)
PQ − CQ  = PQ + ΔP·Q − CQ + P·ΔQ + ΔP·ΔQ − C·ΔQ
0        = ΔP·Q + P·ΔQ + ΔP·ΔQ − C·ΔQ
ΔQ / Q   = −ΔP / (P + ΔP − C)
         = −ΔP / (CM + ΔP)        # CM = P − C。分母は変更後の貢献利益
```

残る項はすべて Δ を含む。価格変更の評価には変化分だけが関係するからである。単位コストも変わる場合は C を C + ΔC に置けば −ΔCM / 新CM が得られる。値上げは P + ΔP、Q + ΔQ を初期状態と読み替えれば同じ図で説明できる。

## `scripts/pricing/breakeven.py` の入力スキーマ

```json
{
  "currency": "USD",
  "unit": "per seat per year",
  "baseline": {"price": 100, "unit_cost": 40, "volume": 1000},
  "volume_unit": "seats",
  "candidates": [
    {"price": 90, "expected": "+5〜10%", "verdict": "不可"},
    {"price": 110, "unit_cost": 42},
    {"price": 120, "incremental_fixed_cost": 20000}
  ],
  "volume_scenarios_pct": [-30, -15, 0, 15, 30]
}
```

共食いモード（既存ティアの横に安いティアを追加する場合）:

```json
{
  "currency": "USD",
  "cannibalization": {
    "full": {"price": 120000, "unit_cost": 45000, "volume": 80},
    "lite_candidates": [{"price": 60000}, {"price": 75000, "unit_cost": 40000}],
    "downgrade_rates_pct": [5, 10, 20],
    "lite_fixed_cost": 0
  }
}
```

Lite の価格ごとに、純置換比率・総置換比率と、各乗り換え率で損益分岐に必要な新規 Lite 数量を出力する。Lite 候補の `unit_cost` を省略すると Full の単位コストを使う。

`baseline.volume` は省略できる。省略するとパーセントだけを出力する。`volume_scenarios_pct` の既定値は `[-30, -15, 0, 15, 30]` で、利益影響の行を出力する。

簡易実行は `--price 10 --cost 5.5 --candidates 9.5,10.5 --volume 4000`、JSON 入力は `--input <file>`、機械可読出力は `--json` を付ける。

反応的モードは `--reactive` を付けるか、JSON の最上位に `"reactive": true` を加える。現行より低い候補ごとに、追随が得になる販売損失の閾値（(CM前 − CM後) / CM前）を別の表で出力する。

スライドを作るとき（`--slides DIR`、`--slides-logic`）だけ使う任意の項目: `volume_unit`（販売量の単位。計算ロジックで「30 テナント」のように付く）、候補ごとの `expected`（見込みの数量変化）と `verdict`（判定）、競合対応の `expected_loss`（見込みの流出率）。金額には `currency` が付く。

## よくある失敗と対処

| 失敗 | 対処 |
|---|---|
| 完全配賦の平均コストを下回る価格を却下する | 増分・回避可能コストで評価する。平均以下でも利益を生む販売はある |
| 開発費を回収するために価格を上げる | 埋没費用は価格決定に無関係。上乗せすると販売が減り損失が広がる |
| 放っておいても伸びた分を値下げの効果とみなす | 成長を織り込んだベースラインと比べる |
| 低価格ティアの売上だけを見る | 失う Full の貢献（機会費用）を差し引く |
| 数量ベースの変化率を売上高の変化率として報告する | 金額ベースの式で換算する |
| 半固定費の階段を無視する | シナリオ表で固定費の増加点を確認する |
| 弾力性が分からないので決めない | 必要な弾力性を計算し、それより大きいか小さいかを判断する |
| 長期の戦略的理由で短期の損失を見ない | まず短期の利益影響を数字にしてから戦略的考慮を重ねる |
