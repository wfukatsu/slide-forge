# 価格構造

セグメントごとに価値やサービスコストが違うとき、「誰がどの束を、どの単位で、どの条件で買うか」を設計する方法を扱う。価値カスケード（価値の創造 → 価値の伝達 → 価格構造 → 価格ポリシー → 価格水準 → 価格競争）の 3 段目で、推定した価値とセグメントを価格表の骨格に変える段階で使う。

## 要点

- 単一価格は高価値顧客には安すぎ、低価値顧客には高すぎる。価格構造（price structure）は価格を価値とサービスコストの差に揃え、個別交渉なしに価格差を付ける。5 セグメントの例では、価格点を 1→2→5 に増やすと貢献利益（(価格 − 単位あたり増分コスト) × 数量）が $2,750→$3,800→$4,950（千ドル）と約 80% 増える（[1] Exhibit 4-1）。
- 仕組みはオファー構成（offer configuration）、価格メトリクス（price metric）、価格フェンス（price fence）の 3 つである。執行しやすさはこの順で、通常は組み合わせる。
- 高価格側の顧客は安い側に化けようとする。グレーマーケット転売や、営業に値引き裁量を与える柔軟価格（flexible pricing）は、価格を価値でなく交渉力の順に並べる。だから構造は先回りして設計する。
- バンドリングは、要素の重要度の順位がセグメント間で逆転しているときに効く。変動費のかかるサービスを無料で同梱すると高コスト顧客が集まるので、戦略的にアンバンドルする。
- 価格メトリクスは「支払 1 単位で何を受け取るか」を決める。5 基準で採点し、1 つで満たせなければ基本料＋従量の複数部構成にする。
- 価格フェンスは、同じ製品・同じメトリクスに異なる価格水準を適用するための資格条件である。必ず漏れを検査する。
- セグメンテーションは [economic-value.md](economic-value.ja.md) で作る。一次セグメントは求める便益が違う顧客群、二次セグメントはその中を最も差の大きい価値ドライバーで切った顧客群である。

## 判断基準・使い分け

| 価値差の源泉 | 仕組み | 執行難易度 |
|---|---|---|
| 必要な機能・サービスが違う | オファー構成（束・階層） | 低（顧客が自己選択する） |
| 利用量・利用強度・成果が違う | 価格メトリクス | 中（測定できるかによる） |
| 製品も用途も同じだが支払能力・代替品が違う | 価格フェンス | 高（越境されやすい） |

### オファー構成の型

| 型 | 使う場面・要点 |
|---|---|
| 階層（good/better/best） | 必要な機能が段階的に違う。3 つ前後。下位版は高価値層だけが重視する価値を抜いて作る |
| 混合バンドル | 評価順位が逆転している。個別価格の合計を束の参照価値（reference value、顧客が比べる基準となる価格）として見せる |
| セグメント特化の付加 | 値下げの代わりに、低価格でないと来ない層だけが喜ぶ付加を束ねる |
| 選択的醜化（selective uglification） | 低価格版に、高価値層にとっての価値だけを損なう条件を加える（割引運賃の土曜泊条件） |
| アンバンドル／オプション | 顧客ごとにコストが変わるサービスは従量課金か上位階層限定にする。無料に慣れた顧客には「使わなければ払い戻す」形で導入する |

### 価格メトリクスの 5 基準（採点テンプレート）

各候補を 0〜2 点（0=満たさない、1=部分的、2=十分）で採点し、根拠を 1 行書く。

| 候補 | ①価値差 | ②サービスコスト差 | ③測定・執行 | ④競合比較 | ⑤価値体験 | 合計 | 根拠 |
|---|---|---|---|---|---|---|---|
| 例: ユーザー数 |  |  |  |  |  |  |  |
| 例: 基本料＋件数 |  |  |  |  |  |  |  |

- ① 得る価値が大きい顧客ほど多く払うか（抗うつ薬 Prozac の「1 日の治療あたり」）
- ② サービスコストが増えると収入も増えるか（住宅配達の追加料金）
- ③ 双方が争いなく数えられるか（自己申告より公表指数・計測値）
- ④ 単価比較で不利に見えないか（コールセンター向けソフトは「分あたり」で 72% 高いが「完了コールあたり」では 11% 安い。[1] Exhibit 4-5）
- ⑤ 買い手が価値を感じる単位か（DVD レンタルの同時貸出枚数制の月額）

容量系はコストに沿うが価値に沿いにくい。成果連動価格（performance-based pricing）は価値に沿い性能リスクを売り手に移せる（GE90 の飛行時間あたり課金）が、測定の合意と顧客データが要る。無理なら価値とコストを「おおむね予測する」代理指標を探す。

### 価格フェンスの類型

| 類型 | 例 | 主な漏れ方 |
|---|---|---|
| 買い手の識別 | 学生・シニア・非営利割引、クーポン（自己識別） | 資格の偽装 |
| 購買場所・チャネル | 地域別価格、チャネル別価格、運賃吸収 | 並行輸入、転売 |
| 購買時期 | 閑散時間割引、優先価格（新製品を高く出し段階的に下げる） | 買い控え |
| 購買数量 | 数量割引、二部料金 | 共同購買による合算、注文分割 |
| 製品設計 | 機能制限版、選択的醜化 | 低価格版で高価値用途を満たせる |

[1] のフェンスは前の 4 類型で、製品設計はオファー構成として扱われる。漏れ検査をまとめるためここに入れた。

### 数量割引・二部料金・タイイン

| 手段 | 使う場面 |
|---|---|
| ボリューム割引（期間累計） | 大口顧客の維持 |
| 注文割引（1 回の量） | 注文処理・配送コストの削減 |
| ステップ割引（閾値を超えた分だけ） | 小口分の単価を守りつつ別用途の需要を取る（電力のブロック料金） |
| 二部料金（two-part pricing: 固定＋従量） | 新規顧客の獲得・訪問に固定的なコストがかかり、追加量の限界コストは低い |
| タイイン（tie-in） | 使用強度で価値が違う資本財。本体を安くし、専用消耗品に上乗せする。契約で強制するのは法的に難しく、技術設計で行う（法的論点は [ethics-legal.md](ethics-legal.ja.md)） |

## 手順

1. **セグメントを受け取る**。一次セグメントは別オファーで、二次セグメントはメトリクスとフェンスで分けるのが原則である。
2. **価値とサービスコストを並べ、価格点の数ごとに貢献利益を試算する**。
   ```
   単一価格 P の貢献利益 = Σ_{WTP_i ≥ P} N_i × (P − VC_i)
   セグメント別価格の貢献利益 = Σ_i N_i × (P_i − VC_i)   （P_i ≤ WTP_i）
     N_i: 数量、WTP_i: 支払意思額（willingness to pay）、VC_i: 単位あたり変動費
   ```
   増分が複雑さと執行のコストを上回る範囲で価格点を増やす。
3. **オファー構成を決める**。セグメントごとに必須・重視・不要な要素を分け、型の表から選ぶ。
   ```
   束が有利な条件: 各セグメントの合計 WTP の最小値 > 個別価格で全セグメントを取れる価格の合計
   例: A 層 $18/$23、B 層 $6/$33 → 個別なら上限 $6+$23=$29、束なら $39 で両方加入
   ```
4. **価格メトリクスを採点する**。候補 3〜5 個を 5 基準で採点する。①と②を 1 つのメトリクスで両立できなければ複数部構成にする。
5. **顧客規模の分布で比較する**。`scripts/pricing/structure_compare.py`（基本料＋段階別従量単価の候補ごとに、顧客規模別の支払額と総収入・貢献利益を計算する）に、顧客規模と顧客数の一覧と候補を JSON で渡す（スキーマはスクリプト冒頭）。極端に割高・割安な規模帯や、競合と支払額が交差する規模を確認する。スライドを作るときは、案ごとの `short`（列見出し用、12 字まで）と `recommended`（指標を示す案の名前）を足す。計算ロジックの金額には `currency`、件数には `unit_label` が単位として付く。
6. **価格フェンスを設計する**。二次セグメントごとに資格条件を類型の表から選ぶ。
7. **漏れを検査する**。各フェンスで「高価格側の顧客が低価格の入口から買えるか」（偽装、転売、分割・合算、時期ずらし、低価格版での代替）を問い、可能なら検証の手間か規則を加える。
8. **成果物**: 一次セグメントごとに「オファー／階層、メトリクス、定価（仮置き）、フェンス、サービスコスト注記」の表を作る。水準は [price-level.md](price-level.ja.md)、取引条件は [pricing-policy.md](pricing-policy.ja.md) で詰める。

## チェックリスト

- [ ] 各価格差が価値差かサービスコスト差で説明できる
- [ ] 下位階層は高価値層だけが重視する価値を抜いて作り、上位からの格下げ流出を検討した
- [ ] 顧客ごとにコストが変わるサービスを無料で同梱していない（していれば理由がある）
- [ ] 候補メトリクスの 5 基準採点表がある
- [ ] 顧客規模の分布で支払額を試算した
- [ ] すべてのフェンスに漏れ検査の結果がある
- [ ] 数量割引は増分に効く形で、既存量に遡及していない

## よくある失敗と対処

| 失敗 | 対処 |
|---|---|
| 業界慣習のメトリクスをそのまま使う | 5 基準で代替を採点する。慣習を変えた企業がマージンを得てきた |
| 差別化のため有償サービスを無料で付ける | 従量化か上位階層への限定に切り替える |
| 営業裁量の値引きでセグメント価格を実現する | オファー構成とフェンスで先回りして差を付ける |
| 成果連動価格を測定手段なしで約束する | 代理指標か、基本料＋成果ボーナスにする |
