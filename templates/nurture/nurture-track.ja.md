## 7. パワースクリプト

営業・インサイドセールスが**語る順番**と、顧客から出るであろう疑問での分岐。
元シートで「作る」とされたまま未着手になっている部分（`nurture-map.ja.md` §7-1）。

### 語る順番

```
1. 状況の確認（〜という状況ではありませんか）
2. 顧客が気づいていない不都合の提示
3. 放置した場合に起きること
4. 解決の方向性（製品名を出す前）
5. Scalar での解き方
6. 次の一歩の提案
```

### 想定される疑問と分岐

| # | 顧客の疑問・反論 | 返し方 | 出す材料 | この後の分岐 |
|---|---|---|---|---|
| 1 | 今のままでも動いています | | | 動く → 段 1 へ／動かない → Re-Engagement |
| 2 | 自分たちで作れます | | | |
| 3 | 他社製品でもできませんか | | | |
| 4 | 実績はありますか | | | |
| 5 | 費用はどれくらいですか | | | |

**答えられない質問は、答えを作らずに「持ち帰る」と書く。**

## 8. 商談への引き渡し

MQL / SQO の定義は元シートに無いため、商談側のゲートを使う
（`nurture-map.ja.md` §2、`sales-playbook.ja.md` §2 フェーズ 1）。

| 判定 | 条件 | 状態 | 根拠 |
|---|---|---|---|
| MQL → SQO を打診してよい | `g1.problem-recognized` — 顧客自身が課題を認識している | unmet | |
| 商談 1 を開始してよい | `g1.owner-reached` — 課題の所有者に到達、または紹介の合意 | unmet | |
| 商談 2 へ進める | `g1.timeframe-6q` — 6 四半期以内の意思決定 | unmet | |

判定は `met` / `partial` / `unmet`。**資料のダウンロードやセミナー参加は
SQO の根拠にならない。**

| 項目 | 内容 |
|---|---|
| 引き渡し先（AE） | |
| 引き渡し時に渡すもの | 接触履歴／閲覧したコンテンツ／出てきた質問／未回答の質問 |
| 商談側の記録先 | `accounts/<AE 名>/<顧客名>/stages/`（`templates/sales/`） |
