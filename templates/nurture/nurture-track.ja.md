## 7. パワースクリプト

営業・インサイドセールスが**語る順番**と、顧客から出るであろう疑問での分岐。
元シートで「作る」とされたまま未着手になっている部分（`nurture-map.ja.md` §7-1）。

### 語る順番

```
1. 状況の確認（〜という状況ではありませんか）
2. 顧客が気づいていない不都合の提示
3. 放置した場合に起きること
4. 解決の方向性（製品名を出す前）
5. Scalar での解き方
6. 次の一歩の提案
```

### 想定される疑問と分岐

| # | 顧客の疑問・反論 | 返し方 | 出す材料 | この後の分岐 |
|---|---|---|---|---|
| 1 | 今のままでも動いています | | | 動く → 段 1 へ／動かない → Re-Engagement |
| 2 | 自分たちで作れます | | | |
| 3 | 他社製品でもできませんか | | | |
| 4 | 実績はありますか | | | |
| 5 | 費用はどれくらいですか | | | |

**答えられない質問は、答えを作らずに「持ち帰る」と書く。**

## 8. 商談への引き渡し

MQL / SQO の定義は元シートに無いため、商談側のゲートを使う
（`nurture-map.ja.md` §2、`sales-playbook.ja.md` §2 フェーズ 1）。

| 判定 | 条件 | 状態 | 根拠 |
|---|---|---|---|
| **MQL に達している** | **課題があることを、買い手が自分の言葉で言える**（段 1 Need 以上） | unmet | |
| MQL → SQO を打診してよい | `g1.problem-recognized` — 顧客自身が課題を認識している | unmet | |
| 商談 1 を開始してよい | `g1.owner-reached` — 課題の所有者に到達、または紹介の合意 | unmet | |
| 商談 2 へ進める | `g1.timeframe-6q` — 6 四半期以内の意思決定 | unmet | |

判定は `met` / `partial` / `unmet`。**資料のダウンロードやセミナー参加は
SQO の根拠にならない。**

MQL の根拠に書けるのは、**買い手が発した言葉**（問い合わせ本文・質疑・投稿・自由記述）
である。こちらが提示した課題の言い換えは根拠にならない。行動ログから状態を推定した
場合は、**推定であると明記する**（`nurture-map.ja.md` §2）。

### 引き渡し先の商談ステージ

**段の番号を、商談ステージにそのまま写さない。**
商談ステージは、ゲートが実際に満たされている最上位のステージで決める
（`nurture-map.ja.md` §2）。

| 項目 | 内容 |
|---|---|
| 起票する商談ステージ | **原則 1。** `g1.*` を先に判定する |
| 顧客側の検討が先行している場合の観測（あれば） | |
| 飛ばさずに取るもの | `g2.goal-agreed`（業務ゴールの合意）／ `decisionCriteria`（評価軸） |
| discovery を短縮した場合、落としたもの | （`deal-log.md` §3 のリスクにも書く） |
| 危険なサイン | RFP・締切・仕様書だけが渡され、ヒアリングの時間が無い → 他社が要件を書いている可能性 |

とくに段 4（Selection）から来たリードは、**「商談 4 に居る」のではなく
「商談 1 に居て、顧客の時計だけが商談 4 に進んでいる」**と読む。

| 項目 | 内容 |
|---|---|
| 引き渡し先（AE） | |

## 9. 指標

**元シートには指標が一切無い**（`nurture-map.ja.md` §7-10）。ここは補って埋める。

**目標値はまず空のままにする。** 1〜2 四半期の実績を取ってから置く。
**測定元（どこの何を見るか）は先に決める** — 決めていないと実績すら取れない。

| 指標 | 定義 | 測定元（MA / CRM の項目） | 目標 | 実績 | 測定日 |
|---|---|---|---|---|---|
| 段 0 → 1 の移行率 | 段 0 のリードのうち、期間内に段 1 と判定された割合 | | （実績待ち） | | |
| 段 1 → 2 の移行率 | 同上（1 → 2） | | （実績待ち） | | |
| 段 2 → 3 の移行率 | 同上（2 → 3） | | （実績待ち） | | |
| 段 3 → 4 の移行率 | 同上（3 → 4） | | （実績待ち） | | |
| MQL 数 | 期間内に MQL の閾値（§8）に達した件数 | | （実績待ち） | | |
| SQO 化率 | MQL のうち `g1.problem-recognized` が `met` になった割合 | | （実績待ち） | | |
| SQO からの受注率 | SQO のうち受注に至った割合 | | （実績待ち） | | |
| Re-Engagement からの復帰率 | 停止したリードのうち、いずれかの段に戻った割合 | | （実績待ち） | | |

**仮の目標を入れない。**「（実績待ち）」は空欄ではなく、まだ置いていないという記録である。

**実績値の正本は CRM / MA 側**にある。この表はトラック 1 本ぶんの転記であり、
テリトリー全体のステージ別勝率・平均サイクル・段別移行率は CRM で見る
（`sales-playbook.ja.md` §8）。**ここで集計し直さない。**

段の判定は買い手の状態で行う（§8）。**MA の行動スコアをそのまま段として集計しない。**
測定元の欄には、その状態をどう記録しているか（リードステータス、カスタム項目名）を書く。
