## 1. 台帳

**2 表に分けてある。**（1-1）が「何のコンテンツか」、（1-2）が「今どうなっているか」。
`Contents ID` で突き合わせる。1 コンテンツにつき、両方に 1 行ずつ。

### 1-1. 識別と分類

| Contents ID | コンテンツ名 | コンテンツのゴール | 製品・ソリューション | 対象ステージ | 対象セグメント | 形式 |
|---|---|---|---|---|---|---|
| C-001 | | | ScalarDB / ScalarDL | 0 / 1 / 2 / 3 / 4 | | 記事 / スライド / ホワイトペーパー / デモ / サンプルコード / 動画 / 見積ツール / テンプレート |

**「コンテンツのゴール」は、読んだ人がどの状態になるかで書く。**
「ScalarDB を紹介する」ではなく「異種 DB 間で整合性が取れないことが自社の問題だと
認識する」のように書く。

### 1-2. 運用状態

| Contents ID | 前提（読み手に求める状態） | 所在 | オーナー | 作成日 | 状態 |
|---|---|---|---|---|---|
| C-001 | | | | | 企画 / 制作中 / 公開 / 要更新 / 廃止 |

**（1-1）に行があって（1-2）に無いコンテンツは、所在もオーナーも決まっていない
＝存在しない。** 企画のまま止まっているものは `状態 = 企画` で（1-2）にも行を作る。
