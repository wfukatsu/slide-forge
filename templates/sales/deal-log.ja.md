**フォーキャストの定義**（プレイブック §4）— `Pipeline` リスクが十分に把握できていない

自社と顧客の**合意した行動**でコントロールできる ／ `Closed` 契約・注文が完了している。

## 1. 面談・やりとりの履歴

新しいものを下に足す。「顧客の発言」と「こちらの解釈」を混ぜない。

| # | 日付 | 形式 | 顧客側の出席者 | 自社・パートナー側 | 主題 | 決まったこと（顧客の言葉） | こちらの解釈 | 顧客側の宿題 | 自社側の宿題 | 次回 | 温度感 | 出典 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | | 訪問 / Web 会議 / 電話 / メール / 展示会 | | | | | | | | | 高 / 中 / 低 / 不明 | |

**温度感はこちらの観察**であり、顧客の発言ではない。根拠（何を見てそう判断したか）を
出典欄に書く。書けないなら `不明` にする。

### ステージ遷移の履歴

ヘッダの「現在のステージ」はスナップショットで、**いつ変わったかを持たない**。
サイクルタイムはここからしか出せないので、**遷移のたびに 1 行足す**。

| # | 日付 | 遷移前 | 遷移後 | 判定に使ったゲート | 顧客側の証拠 | 前ステージの滞留日数 |
|---|---|:-:|:-:|---|---|---|
| 1 | | | | | | |

- **戻した場合も 1 行**（`2 → 1` など）。巻き戻しを消さない
- 証拠が書けない遷移は、そもそも遷移させない（プレイブック §1 原則 5）
- 滞留日数は前行の日付との差。**集計はここでしない**。テリトリー全体の平均サイクルは
  CRM で見る（プレイブック §8）

### 記録が既存の内容と矛盾したとき

| # | 以前の記録（場所） | 今回の材料 | どちらを採るか | 判断の根拠 | 再確認の要否 |
|---|---|---|---|---|---|
| 1 | | | | | 要 / 不要 |

## 3. リスクと対策

**未確認事項（＝聞けば分かること）とは別物。** ここには、既知だがこちらで
コントロールしきれないものを書く（プレイブック §7 の 10 問・9 番）。

| # | リスク | 種別 | 影響 | 発生可能性 | コントロールする次の行動 | 期限 | 担当 | 状態 |
|---|---|---|---|---|---|---|---|---|
| 1 | | 予算 / 決裁 / 競合 / 技術 / パートナー / 人事異動 / 優先度低下 / 法務・契約 / 時期 | 大 / 中 / 小 | 高 / 中 / 低 | | | | 未着手 / 対応中 / 解消 |

**フォーキャストとの対応** — 未解消の「影響: 大」が 1 つでもあり、次の行動が
顧客と合意できていないなら `Commit` にしない。

## 4. 商談の結末の記録

**結果が出た時点で埋める。埋めずに閉じない。受注も同じ。**
勝ちと負けを同じ場所・同じ粒度で残すために、1 つの節にまとめてある。

### 共通

| 項目 | 内容 |
|---|---|
| 結果 | 受注 / 失注 / 保留（再開見込み時期: ） / 見送り（こちらから） |
| 判明日 | |
| その時点のステージ | |
| **分かれ目になった評価軸** | |
| 顧客が挙げた理由（**発言のまま**） | |
| こちらの分析（真因） | |
| 商談を通じて得た資産（関与者との関係、把握した業務・システム） | |

### 受注のとき

| 項目 | 内容 |
|---|---|
| 決め手になったもの（顧客の発言があれば引用） | |
| 効いた材料（資料・デモ・PoC・事例・リファレンス） | |
| 競合が居た場合、何で上回ったか | |
| Champion が社内で使った説明 | |
| 想定より時間がかかった工程と、その理由 | |
| **次の商談で再現したい動き** | |
| 再現できなかった場合に効かなくなる前提 | |

### 失注・保留のとき

| 項目 | 内容 |
|---|---|
| 採用された相手 | 競合（社名） / 内製 / 現状維持 / 予算不成立 / 案件そのものが消滅 |
| いつ戻れば防げたか（どのステージの、どの確認漏れか） | |
| 再アプローチの条件 | |
| 次の接触予定 | |

**「価格が高い」を真因として採らない。** 価格が理由に挙がる場合、ほぼ常に
価値の合意（Metrics）か評価軸（decisionCriteria）の作り込み不足が先にある。

**受注の「決め手」も、顧客が言っていないなら推測として書く。** 勝った商談の
自己申告は、負けた商談の自己申告より甘くなる。
