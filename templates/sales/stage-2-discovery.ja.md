## 10. MEDDPICC の充足状況（台帳との対応）

`account.json` の `discovery` は MEDDPICC ＋「なぜ今か」で構成される。
このステージの終わりに、9 項目がどこまで埋まったかを 1 枚で見る。
**状態は `confirmed` / `wip` / `missing` の 3 値**（台帳の `DISCOVERY_STATUS` と同じ）。

| 台帳キー | 日本語 | このファイルでの記録先 | 状態 | 根拠（顧客側の証拠） |
|---|---|---|---|---|
| `identifiedPain` | 課題 I | §3 業務課題 | missing | |
| `metrics` | 指標 M | §3 Metrics | missing | |
| `compellingEvent` | 決め手 Ce | §3 Compelling Event | missing | |
| `economicBuyer` | 決裁者 E | §1 Economic Buyer | missing | |
| `decisionCriteria` | 評価基準 D | §8 評価基準 | missing | |
| `decisionProcess` | 決裁プロセス P | §10 決裁プロセス（下表）／`deal-log.md` §2 | missing | |
| `champion` | 推進役 C | §1 Champion の検証 | missing | |
| `competition` | 競合 Co | §8 競合リスト | missing | |
| `paperProcess` | 契約手続 Pa | ステージ 4 §12 | missing | |

`confirmed` にできるのは、**顧客側の証拠**が書ける場合だけ。書けないものは `wip` に留め、
§11 のアクションに落とす。

> `paperProcess` はステージ 4 §12 で埋まる項目である。**ステージ 2 の時点で
> `missing` のまま残るのが正常**で、これを未達として扱わない。ただし、購買・法務の
> 所要期間が読めないままクローズ予定日を置くことはできないため、
> **遅くともステージ 3 の終わりまでには聞き始める**（ヒアリングシート §10 の契約欄）。
