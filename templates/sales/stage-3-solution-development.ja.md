### PoC の設計（実施する場合）

**PoC が終わっても買わない**のは、合否基準と、合格した場合に顧客が何をするかを
先に決めていないことが原因である。実施を合意する前に、この表を埋める。

| 項目 | 内容 | 顧客と合意済み |
|---|---|:-:|
| PoC の要否 | 不要 / 実施 | — |
| 検証する仮説（何が不明だから実施するのか） | | 未 / 合意 |
| 検証しないと明示すること | | 未 / 合意 |
| 対象範囲（データ・機能・環境） | | 未 / 合意 |
| 期間（開始日・終了日） | | 未 / 合意 |
| **合否の判定基準（数値で）** | | 未 / 合意 |
| 判定する人（氏名・役職） | | 未 / 合意 |
| 判定の場（どの会議体で、いつ） | | 未 / 合意 |
| 顧客側の体制と工数 | | 未 / 合意 |
| 自社・パートナー側の体制と工数 | | 未 / 合意 |
| 費用負担（有償 / 無償） | | 未 / 合意 |
| **合格した場合に顧客が次に行うこと** | | 未 / 合意 |
| 不合格だった場合の扱い | | 未 / 合意 |

「合格した場合に顧客が次に行うこと」が `未` のまま PoC を始めない。
そこが空欄の PoC は、フォーキャストを `Best` より上げる根拠にならない。
