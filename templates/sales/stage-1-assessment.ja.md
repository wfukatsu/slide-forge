## 6. ステージ移行判断

シート記載の判断基準と、プレイブックのゲート ID を併記する。
**「説明した」「資料を送った」は移行の根拠にならない。顧客側の証拠を書く。**

| ゲート ID | 移行条件 | 判定 | 顧客側の証拠（誰が・いつ・何と言ったか） |
|---|---|:-:|---|
| `g1.problem-recognized` | Scalar で解決可能な課題を**顧客自身が**認識している（シート記載） | unmet | |
| `g1.timeframe-6q` | 意思決定のタイムラインが 6 Qtr 内（シート記載） | unmet | |
| `g1.owner-reached` | 課題の所有部門・責任者につながっている、または紹介が合意されている | unmet | |
| `g1.linked-to-exec` | 経営・部門課題との関係が確認できている | unmet | |
| `g1.next-discovery-agreed` | 次回のディスカバリー対象者とテーマが合意されている | unmet | |

判定は `met` / `partial` / `unmet` で書く（台帳の `GATE_STATUS` と同じ語彙）。
**`met` にできるのは、顧客側の証拠が書ける場合だけ。**

**判定**: ステージ 2 へ移行する / このステージを継続する / 見送る（理由: ）

**ステージ 2 へ引き渡すもの**: 課題適合性の判定 ／ 予算スケジュール ／
初期インフルーエンスマップ ／ 次回ディスカバリーの対象者とテーマ
